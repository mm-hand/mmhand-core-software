# P4 架构迁移实施记录

## 目标

将 P4 固件整理为 `app/config/data/generated/hal/modules/platform/runtime/safety/tasks` 分层；每个 RTOS Task 的入口、Service 和私有工具归入同一任务包，跨任务只共享协议、纯算法、消息端口与受控运行时状态。

## 执行原则

- 先移动目录和改名，再拆大文件，最后收口共享状态与 NVS 所有权。
- 不修改任务周期、优先级、PID 参数、标定阈值、状态迁移条件和线协议长度。
- 每个阶段完成后执行旧符号扫描、架构检查和可用的编译/测试。
- 任一临时兼容别名都必须记录，并在最终阶段删除。
- 中文文件头保持 `@file`、`@brief`、`@details` 格式一致。

## 已完成记录

- 启动装配迁入 `app/`，日志迁入 `platform/log/`，运行时状态、端口、通道和适配器迁入 `runtime/`。
- 建立 `host_comm/system_state/s3_can_rx/servo_bus/motion_control/nvs_persistence/runtime_monitor/auto_calibration` 八个任务包。
- Task 私有 Service、状态机和工具函数已跟随任务包移动；共享标定数据仓库改名为 `CalibrationRuntimeStore`。
- CRC16-CCITT/FALSE 与 CRC32/IEEE 已分别集中到 `modules/integrity`，协议、S3 CAN、Manual NVS 和多圈 NVS 不再保留重复实现。
- Runtime Metrics 已迁入 `runtime/metrics/TaskRuntimeMetrics.*`，旧 `system` 目录不再承载运行逻辑。
- 全局 `TaskSharedData_t` 已改名为 `SystemRuntimeContext`，任务名统一为 Host/State/S3/Servo/Motion/NVS/Monitor/Calibration 职责名。
- Manual 标定保存和多圈 NVS 开关/清空已改为 Host 投递、`NvsPersistenceTask` 单点写 Flash、Host 消费读回结果；维护请求使用顺序 `send`，禁止覆盖已经 ACK 的事务。
- S3 磁编健康去抖拆入 `EncoderHealthMonitor`，Host ACK FIFO 拆入 `HostAckPublisher`，Servo 物理路由/总线初始化/多圈恢复入口拆入 `ServoBusRouting`；原有 State、Control、Host、Servo 任务私有工具均保留在各自任务包。
- 架构门禁已更新为当前十个顶层目录、八个任务包、`SystemRuntimeContext` 组合、NVS 单写者和当前文件路径；安全闭环检查恢复为 101/101 规则、7/7 干预点通过。
- 主架构文档、P4 README 与 `generate_robot_model.py` 模板已同步新路径；生成器不再回退输出旧 `system/SystemContext.h`。
- 批量路径校正曾因本机 .NET 不支持 `Path.GetRelativePath` 产生 48 个空 include；已依据 `.debug/p4/sketch/src` 构建快照和编译诊断全部清除并恢复直接依赖，业务代码未回滚。
- Desktop 已适配持久化命令的异步 ACK：Manual 写入/清除和多圈 Flash 开关接受 `QUEUED` 后，分别等待带时间戳的 Manual 结果包或系统状态包确认最终 Flash 状态；排队成功不再误报完成，超时、失败或读回不一致仍返回失败。
- 最终旧符号扫描确认 `TaskSharedData_t`、`UpperCommTask`、`ServoCommunicationTask`、旧 `system/SystemContext.h` 引用均为 0；迁移后遗留的 `system/context` 与 `modules` 下 6 个空目录已清除。
