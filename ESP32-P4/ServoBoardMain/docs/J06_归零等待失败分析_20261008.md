# J06 logical ABS zero failed：归零等待失败分析

最初的固件清理阶段仅修改 P4，保留上位机原样；随后按用户要求修复了本文所述
上位机问题，具体变更及验证见文末。

## 日志能够确认的事实

记录来源：`run_data/数据记录_20261008_191118/08_原始接收帧.csv`。

| 事件 | P4 时间 ms | 含义 |
| --- | ---: | --- |
| F0 结果 token 9，success mask `0x100` | 444149 | J06 对应 M08 已归零；新 raw 2261，offset -2261，logical ABS 0 |
| logical range | 444152 | 新范围已上报，有效位 `0x07FFFFFF` |
| 第一条 STOP ACK | 444202 | 归零结果之后仅 53 ms 已发生停止 |
| 同戳 raw / ABS | 444224 | 此次归零后的成对反馈确实到达过 |
| 错误文本中的最新 raw | 444266 | 此时 ABS 仍为 444224，raw 已独立更新 |
| 恢复 scope / 第二条 STOP ACK | 444287 | 工作流已进入退出清理阶段 |

这不是“没有发送 F0”：归零结果和后续 ABS=0 均有实际协议证据。
从上述时间看，本次停止与 3000 ms 等待自然超时不符。

## 错误文本为什么会误导

`desktop/core/host_calibration/runtime.py` 的 `_wait()` 对取消和超时都返回 `False`。
`_rebase_and_wait()` 随后统一输出 `waiting for post-rebase ABS/raw anchors and logical range`，
因此该文本也可能表示等待已被 STOP 取消。它不是 P4 返回的归零失败码。

`desktop/core/comm_layer.py` 中 STOP 会清空待发送队列，待发送的 state sync 也会被清掉。
本次 F0 之后未发现 state sync ACK，与该行为相容。

## 已确认并修正的 P4 上报问题

原 `HostCommService` 开启 control trace 时，ABS 每 50 ms 上报，raw 每个反馈周期上报。
上位机锚点检查要求两个时间戳相同，raw-only 更新会很快覆盖匹配窗口。

现改为同一快照、同一限频条件；两个既有 RAW/ABS 协议帧在一次串口写中发送。
帧编号、字段、长度和时间戳含义保持原样；没有新增标定协议或标定状态。
这修正发包节奏问题，但不解决上位机外部 STOP 取消。

## 符合记录的上位机竞态路径：仍为推断

1. J05 单舵机标定失败但允许继续 J06；`flow.py` 保留上一关节诊断。
2. P4 fault bitmap 为 0 时，该 host diagnostic 本身不会激活 UI 故障处理。
3. J06 的合法 F0 短暂产生 UNKNOWN `0x100`；`ui_app.py` 的 `only_turn_unknown`
   同时要求 host diagnostic inactive，旧诊断使该条件失败，跳过预计归零窗口判断。
4. UI 未显示中间 IDLE 时，`previous_runtime_active` 可延续此前 RUN_DIRECT，触发 STOP。
5. STOP 取消 worker 的等待，却显示成“归零等待失败”。

原始记录中 UNKNOWN 只有 `0x100`，处于此次 F0 的 mask 内；无需假设其它手指未知。
会话内存日志尚未落盘，不能唯一确认首次 STOP 的发送者及 J05 当时诊断值。
状态 CSV 的约 30 秒空窗也不能证明 core 死锁：原始接收持续，模态弹窗与 GUI 快照去重
可以造成显示和状态记录延后。

## 上位机修复与验证

- `desktop/ui/ui_app.py`：仅根据实际设备故障及过载判断是否为唯一 UNKNOWN，
  再交给 core 确认 F0 窗口。历史 host diagnostic 不再阻挡该确认；STOP 和弹窗共用
  同一次确认，避免 STOP 取消事务后第二次判定变化。
- `desktop/core/host_calibration/runtime.py`：等待退出原因区分 ready、cancelled、timeout。
  F0 成功后反馈等待被取消，明确显示归零已经执行；真实超时列出同戳、在线、路由、
  新 logical range 等缺失条件。已完成归零窗口使用实际验收的 Known 锚点时间截止，
  处理 SYSTEM_STATUS 滞后与 uint32 回绕，持续或新增 UNKNOWN 仍按真实故障处理。
- `desktop/core/host_calibration/flow.py`：归零、运动、写回或预检中取消会正确传播；
  保留此前成功及真实失败的关节记录，不把当前被取消关节追加为机械失败，
  不生成额外的提交或汇总故障诊断。
- 同戳 ABS/raw 与新坐标范围准入保持严格；UI 布局、Mechanical 单/双电机算法及
  本轮 P4 固件均未修改。

回归验证：校准核心、归零协议和全部 UI 测试共 **373 passed**。
包含残留 J05 诊断后 J06 F0、混合真实故障必须 STOP、同次确认结果翻转、
取消不冒充超时、取消保留部分结果及设备时钟回绕等场景。实机复测尚未执行。
