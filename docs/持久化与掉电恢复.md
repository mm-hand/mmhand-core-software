# 持久化与掉电恢复

最后核对：2026-08-01

## 1. 为什么不能只保存一个 ABS

飞特舵机返回单圈 raw 和当前会话多圈位置。舵机单独掉电后，硬件会话坐标可能重新从 turn 0 开始；如果 P4 仍把旧 ABS 直接下发，电机会把同一数字解释为新的多圈目标。当前系统把上层坐标定义为 P4 logical ABS，并保存 `turn + raw` 锚点；恢复时先比较新的物理 raw，再计算 `logicalOffset`，保持控制/LUT 坐标连续。

```text
logical ABS = hardware ABS + logicalOffset
```

offset 只改变坐标解释，不会让电机物理转动。所有最终目标仍需通过会话 logical range 和 hardware ABS `[-30719, 30719]` 检查。

## 2. Manual 标定 NVS

Manual Min/Max 使用 namespace `manual_cal`、key `slot0/slot1` 的 A/B 双槽。当前布局 V2 包含 magic `MCAL`、jointCount、sequence、validMask、21 路 min/max、reference CRC 和结构 CRC32；V1 仅用于兼容读取并迁移。

保存流程写入较旧槽、提交、回读并重新校验后才向上位机 ACK。读取时同时检查 magic、version、长度、jointCount、结构 CRC 和端点语义；两个槽都有效时选择 sequence 较新者。A/B 双槽的价值是：写电中断时通常只损坏正在写的槽，另一槽仍可恢复。

Manual 条目改变后，对应 Auto V3 的 `manualReferenceCrc` 不再匹配，必须重新标定；不能仅靠数组长度相同继续复用旧 LUT。

## 3. 多圈快照 NVS

多圈快照使用 namespace `mt_abs`，key 为 `slot0/slot1`，另有用户开关 `enabled`。当前 V2 快照包含：

- magic `MTN1`、version=2、motorCount=27、sequence；
- 可信通道 `validMask`；
- 由 HardwareMap 计算的 `mappingSignature`；
- 27 路 `turns[]`、`raw[]`；
- 结构 CRC32。

`mappingSignature` 覆盖映射版本、电机数、关节数、bus/id、tendon sign、关节执行器组、offset 与 tensionBias。机械拓扑变化后旧快照会被拒绝，防止把 Mxx 的圈数恢复到另一个物理舵机。

局部 active scope 保存时，未包含的通道继承上一份可信值，不会因为只测试一根手指而擦除其他电机的快照。普通保存请求使用容量 1 的 latest queue 合并；Reset Zero 作业不能被后到的普通保存覆盖。

## 4. 为什么 Flash 任务优先级最低

NVS 擦写可能出现毫秒级抖动，而且 Flash 寿命有限。ServoComm 只缓存最新可信/待保存快照，运动 owner 释放后再交给 `MultiTurnNvsPersistenceTask`；NVS 任务优先级 1、队列驱动，检测运动退出后再等待 20 ms。

当前持久化策略还使用：恢复等待 3 s、上位机离线判定 1 s、最小保存间隔 500 ms、离线周期保存 2 s、raw 匹配容差 256 counts、显著移动阈值 64 counts、单圈边界余量 256 counts。它们用于减少写放大并避免在边界/运动中保存不可靠锚点。

## 5. 舵机单独掉电与整机掉电

### P4 仍供电、舵机单独掉电

ServoComm 连续读失败后将通道置 offline，并冻结最后可信 RAM 锚点；舵机恢复后按当前 raw 与锚点寻找合理圈数/offset。在线去抖为连续 2 次读成功，离线去抖为连续 3 次失败；探测间隔 50 ms，最多 3 次恢复尝试，重试间隔 100 ms。恢复期间通道不允许进入普通反馈控制。

### P4 与舵机同时掉电

RAM 锚点会丢失，只能使用断电前已成功写入 NVS 的快照。若断电发生在运动中且最新姿态尚未提交，恢复的是上一次可信快照，而不是断电瞬间的位置。这是当前硬件条件的物理限制，文档不能承诺“任意时刻掉电都零误差恢复”。

## 6. Reset Zero

Reset Zero 用于舵机硬件多圈位置接近范围边界时重建 turn 0。触发关注值为 `-30715/+30715`，真正命令仍由 driver 的 `[-30719,30719]` 硬边界保护。

执行前要求：无 active owner、control disabled，且状态为 `UNCONTROLLABLE/IDLE/READY/RECOVERY_REQUIRED` 之一。流程是硬件 reset zero、更新 logical offset/范围、原子替换指定通道 NVS 快照、再向上位机报告结果。

一旦物理坐标已被 reset，即使后续 Flash 写失败，相关 calibration 也必须失效；继续使用旧 LUT 比要求重新标定更危险。

## 7. 恢复失败的排查

按顺序检查日志：

1. NVS 用户开关是否 enabled，A/B 槽是否至少一个通过 magic/version/CRC；
2. `mappingSignature` 是否与当前 HardwareMap 一致；
3. 舵机 ID/bus 是否在线，单圈 raw 是否在 256 counts 匹配窗内；
4. 是否处于单圈边界附近，或断电期间机械被手动移动；
5. validMask 是否覆盖当前 active motors；
6. logical range 和 hardware range 是否允许恢复后的坐标；
7. Manual/Auto 的 CRC 与 URDF mapping version 是否仍匹配。

不要为了“恢复成功”放宽 CRC、mappingSignature 或 raw 匹配条件。无法证明圈数时应进入 `RECOVERY_REQUIRED/UNCONTROLLABLE`，通过受控恢复或重新标定建立新锚点。
