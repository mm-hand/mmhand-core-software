# 单腱速度前馈与响应优化说明

本文说明单电机/单腱关节当前的闭环输出、LUT 增益调度，以及速度前馈如何改善响应。本文只描述现有实现与后续建议，不改变协议、标定 LUT 格式或双腱控制路径。

## 1. 目标与范围

单腱关节的磁编码器反馈角度存在机械弹性、摩擦和舵机位置环延迟。只使用位置 PID 时，舵机必须先看到实际角度落后于目标，才会增加输出；对于连续遥操或正弦目标，这会产生相位滞后。

当前速度前馈仅作用于以下条件全部满足的单腱关节：

- 关节在反馈控制掩码内；
- Auto Calibration 和该关节 LUT 有效；
- 主电机在线，磁编码器反馈有效；
- 不属于双腱关节；
- 不处于碰撞 HOLD、标定、直控、暂停或未激活状态。

任何上述条件不满足时，速度前馈状态都会清零，防止上一次遥操的目标速度残留到下一次控制。

实现位置：

- `ESP32-P4/ServoBoardMain/src/config/ControlConfig.h`
- `ESP32-P4/ServoBoardMain/src/tasks/motion_control/MotionControlService.cpp`
- `ESP32-P4/ServoBoardMain/src/tasks/motion_control/ControlSolver.cpp`

## 2. 当前控制输出

对一个单腱关节，本周期最终在腱绳坐标中的位置增量是：

```text
outFinal = outPid + round(ffTendonCounts)
```

其中：

```text
outPid = PID(qRef, qFb, dt)
ffTendonCounts = s * (LUT(qPredict) - LUT(qRef))
```

最终的 `outFinal` 再叠加到当前舵机腱绳 ABS 坐标，随后转换回该电机的 raw ABS 坐标；之后仍经过已有的 LUT 端点、动态 logical 行程、离线保护和碰撞保护。速度前馈不会绕过任何安全钳位。

`s` 是 `getMotorTendonShortenAbsSign()` 返回的方向符号。不同电机 raw ABS 增大的方向可能相反，但通过 `s` 归一后，正的 `ffTendonCounts` 永远表示“按关节正方向推进腱绳”。

## 3. 速度前馈公式与变量

### 3.1 目标速度估计

每个关节独立保存上一周期目标和滤波后的目标速度：

```text
vRaw[k] = (qRef[k] - qRef[k-1]) / dt
alpha   = dt / (tauVelocity + dt)
qDot[k] = qDot[k-1] + alpha * (vRaw[k] - qDot[k-1])
```

| 变量 | 含义 | 当前值或来源 |
|---|---|---|
| `qRef` | 当前周期关节目标角度，已过工作空间限制 | `localTargets[joint]`，单位 deg |
| `qFb` | 当前磁编码器映射角度 | `magAngles[joint]`，单位 deg |
| `dt` | 本次 PID 的真实调度间隔 | `nowMs - lastPidComputeMs`，异常时回退 `10 ms` |
| `vRaw` | 未滤波的目标角速度 | deg/s |
| `qDot` | 一阶低通后的目标角速度 | deg/s |
| `tauVelocity` | 目标速度低通时间常数 | `kSingleTendonTargetVelocityFilterTauSec = 0.040 s` |
| `alpha` | 当前周期低通系数 | `dt / (tau + dt)` |

这里滤波的是**目标速度**，不是反馈速度。它的目的不是制造阻尼，而是避免上位机 33 Hz 的离散目标更新在 100 Hz 控制周期内形成很大的瞬时速度尖峰。

### 3.2 预测目标角度

```text
leadRequested = clamp(Tlead * qDot, -leadMax, +leadMax)
qPredict      = clamp(qRef + leadRequested, qMin, qMax)
qLead         = qPredict - qRef
```

| 变量 | 含义 | 当前值 |
|---|---|---|
| `Tlead` | 预测提前时间 | `kSingleTendonVelocityLeadTimeSec = 0.070 s` |
| `leadMax` | 最大预测提前角 | `kSingleTendonVelocityLeadMaxDeg = 3.0 deg` |
| `qMin/qMax` | 当前关节有效 LUT 的标定角度范围 | `currentMinDeg/currentMaxDeg` |
| `qPredict` | 预计约 `Tlead` 后的目标角度 | deg |
| `qLead` | 真正采用的提前角 | deg |

`qPredict` 必须在 LUT 的角度范围内。即使输入目标或预测值超出 URDF/LUT 行程，参与 LUT 插值的角度仍会被夹住；因此前馈不会因越界查询而制造无效舵机坐标。

例如 `0.2 Hz`、振幅 `20 deg` 的正弦目标，理论峰值速度为：

```text
vMax = 2 * pi * f * A
     = 2 * pi * 0.2 * 20
     = 25.13 deg/s
```

在不触发上限时，最大预测角约为：

```text
qLead ~= 0.070 * 25.13 = 1.76 deg
```

这就是系统在中位附近会提前约 1.7 度下发舵机位置的原因。

### 3.3 将预测角转换为前馈 counts

```text
referenceAbs = LUT(qRef)
predictedAbs = LUT(qPredict)
ffTendonCounts = s * (predictedAbs - referenceAbs)
```

LUT 是“关节角度 -> 对应舵机 ABS”的标定曲线。前馈不假设所有位置具有相同传动比，而是直接在当前关节自身 LUT 上插值两次并做差。因此绳轮半径、绕线变化或局部斜率变化都会自然反映到 counts 前馈量中。

这项输出的实际意义是：PID 尚未因为反馈滞后产生足够误差前，舵机目标已经向未来目标位置推进。它减少的是连续轨迹的相位滞后，而不是替代 PID 纠正最终静差。

## 4. J14 最新实测解释

数据源：`run_data/数据记录_20260827_204720`，J14，`0.2 Hz`，`0-40 deg` 正弦目标。PID 诊断按约 50 ms 输出一次，统计的是日志中的 `qDot/qLead/ff/outPid/outFinal`。

整体结果：

| 指标 | 结果 |
|---|---:|
| 相位延时 | `102.9 ms` |
| 中位延时 | `70.5 ms` |
| 相关峰值延时 | `105 ms` |
| RMSE | `3.28 deg` |
| 峰峰值增益 | `1.017` |
| `|ff|` 中位数 / P95 / 最大值 | `18.1 / 29.5 / 33.9 counts` |
| `|qLead|` 平均 / P95 / 最大值 | `1.03 / 1.90 / 2.02 deg` |
| `ff` 与 `qDot` 方向一致率 | `99.3%` |

前一组未采用当前速度前馈的 J14 `0.2 Hz` 记录，延时约 `245 ms`，中位延时约 `185 ms`，RMSE 约 `5.34 deg`。这表明当前前馈主要改善了连续运动的中段跟随。

按目标位置分箱后的前馈绝对值如下：

| 目标角度 | `|ff|` 中位值 | P95 / 最大值 | 有效 LUT 斜率 |
|---|---:|---:|---:|
| 0-5 deg | 13.0 counts | 26.6 / 28.2 | 20.0 counts/deg |
| 5-10 deg | 20.2 | 30.1 / 30.1 | 16.8 |
| 10-15 deg | 23.6 | 33.9 / 33.9 | 16.8 |
| 15-20 deg | 25.7 | 32.4 / 32.4 | 15.0 |
| 20-25 deg | 23.1 | 28.3 / 28.3 | 14.4 |
| 25-30 deg | 20.8 | 26.4 / 26.4 | 15.7 |
| 30-35 deg | 20.4 | 25.3 / 25.3 | 16.2 |
| 35-40 deg | 9.0 | 17.9 / 18.3 | 15.6 |

真正贴近端点（`qRef <= 1 deg` 或 `qRef >= 39 deg`）时，`|ff|` 中位值只有 `3.7 counts`，最大值 `16.4 counts`。这是合理的：正弦波端点的目标速度接近零，速度前馈应自然消失，避免在机械极限附近继续推送。

最大 `qLead = 2.02 deg` 小于 `3 deg` 上限，说明本次没有被前馈角限幅压平；当前 `70 ms` 提前时间对该频率尚未过大。

## 5. LUT-KP 当前是否为平均斜率

不是单一的“平均斜率 KP”。当前单腱有效 LUT 控制是分段调度：

```text
e        = qRef - qFb
localSlope = abs((LUT(qRef) - LUT(qFb)) / e)
averageSlope = abs(LUT(qMax) - LUT(qMin)) / (qMax - qMin)
```

其中 `localSlope` 是目标与反馈之间当前区间的等效 LUT 斜率；`averageSlope` 是整段标定行程的平均斜率。它们单位都是 counts/deg。

当前有效 `Kp` 为：

| 误差区间 | 实际 Kp |
|---|---|
| `|e| <= 0.8 deg` | 固定 `20 counts/deg` |
| `0.8 < |e| <= 2.5 deg` | 紧绳：`1.0 * localSlope`；松绳：`0.75 * localSlope` |
| `2.5 < |e| < 3.0 deg` | 在局部 Kp 与大误差平均 Kp 之间线性插值 |
| `|e| >= 3.0 deg` | `0.75 * averageSlope` |
| LUT 无效、插值失败或电机方向异常 | 回退固定 `5.7 counts/deg` |

所以回答“当前 LUT 的 KP 是否是平均斜率”：

- 大于等于 `3 deg` 的大误差阶段：**是**，使用本关节全行程平均斜率的 `0.75` 倍；
- `0.8-2.5 deg` 的近端阶段：**不是**，使用当前目标和反馈之间的局部 LUT 斜率；
- 小于等于 `0.8 deg`：也不是 LUT 斜率，而是固定 `20 counts/deg`，用于避免换向时输出过小。

注意：配置注释仍写着“紧绳近端 1.2 倍局部斜率”，但当前实际常量 `kSingleTendonDynamicLutGain = 1.0f`，所以运行行为是 **1.0 倍**，不是 1.2 倍。后续应仅修正文档注释，避免调参时误解；不需要改变控制逻辑。

## 6. PID、速度前馈和 D 项的分工

| 项目 | 输入 | 主要解决问题 | 当前效果 |
|---|---|---|---|
| P 项 | `qRef - qFb` | 消除位置误差 | 最终位置逼近 |
| I 项 | 误差累积 | 消除长期静差 | 当前 `Ki = 0`，未启用 |
| D 项 | 低通后的反馈速度 | 抑制过冲和振荡 | `Kd = 0.10`，限幅 `20 counts` |
| 速度前馈 | 低通后的目标速度与 LUT | 目标连续变化时提前推进 | 主要降低中段相位延时 |

速度前馈不是 D 项：D 项对“实际运动速度”作阻尼，速度前馈对“目标未来趋势”作提前。两者方向和目的不同，可以同时存在。

## 7. 为什么速度前馈不能单独解决换向

正弦目标在波峰和波谷换向时，目标速度必然经过零：

```text
qDot ~= 0 -> qLead ~= 0 -> ffTendonCounts ~= 0
```

因此恰恰在需要克服静摩擦、让腱绳重新受力的瞬间，当前速度前馈自然退出。这是正确的连续轨迹行为，但意味着换向初段仍主要依赖 PID。日志中可看到，误差刚翻到新方向时 PID 往往只有约 `5-15 counts`，可能不足以稳定启动舵机。

此外，目标速度低通的 `40 ms` 时间常数会让 `qDot` 在方向变化后平滑穿过零。它能抑制 33 Hz 上位机离散指令带来的尖峰，但也不应被误认为静摩擦补偿。

## 8. 下一步：受限的换向脱粘前馈

第一优先级不应增大全局 `Kp` 或全局 `Tlead`。当前中位响应已明显改善，直接加大它们会放大中段超调。更合适的是增加一个独立、短时、单次触发的换向脱粘项。

建议的第一组实验参数：

| 参数 | 建议初值 | 目的 |
|---|---:|---|
| 目标累计反向确认 | `0.3 deg` | 排除单帧量化抖动 |
| 脱粘初始量 | `50 counts` | 明显高于换向初段的普通 `5-15 counts` 输出 |
| 衰减窗口 | `40 ms` | 获得起动推力后快速让回 PID + 速度前馈 |
| 提前退出移动量 | `0.25 deg` | 实际已沿新方向移动则停止额外推进 |
| 同方向触发次数 | 一次 | 禁止每 10 ms 重复累加 |

推荐触发逻辑：

```text
1. 新方向的累计目标变化 >= 0.3 deg；
2. qPredict - qFb 已指向新方向；
3. 当前最终 PID/前馈输出尚未足以让反馈转入新方向；
4. 锁存本方向，只触发一次。
```

推荐输出形式不是“注入 80 deg 虚假误差”，而是直接在腱绳坐标中叠加一个有界脉冲：

```text
kick(t) = direction * 50 counts * max(0, 1 - t / 40 ms)
outFinal = outPid + ffTendonCounts + kick(t)
```

这样不会把虚构的角度误差放大成数千 counts，也能继续复用后续所有 LUT、行程和安全钳位。若 `50 counts` 仍无法可靠启动，按 `50 -> 70 counts` 递增；若出现换向超调，先缩短窗口到 `25 ms`，再降低到 `40 counts`。

## 9. 后续验证顺序

1. 固定 J14，先保持当前 `Tlead = 70 ms`、`tauVelocity = 40 ms` 与当前 Kp 不变。
2. 分别运行 `0.2 Hz`、`0.3 Hz`、`0.5 Hz`，振幅 `20 deg` 正弦。
3. 对每次记录统计中位延时、相位延时、RMSE、峰峰值增益、端点超调和换向后首次有效运动时间。
4. 脱粘项只改一个参数：先改 counts，再改持续时间，不同时改变 Kp 或速度提前时间。
5. 确认双腱关节未进入该分支，且到 LUT 两端时 `qPredict` 与最终 raw ABS 仍被原有边界限制。

## 10. 当前结论

当前速度前馈已经以 LUT 的局部实际斜率把“未来约 70 ms 的目标变化”转换为合理的舵机 counts，并显著改善了中位跟随。它应保留。

下一阶段应把“连续轨迹的速度预测”和“换向瞬间的静摩擦脱粘”保持为两个独立项：前者处理相位延迟，后者只处理短时启动不足。这样调参时能够清楚归因，也不会让一个过大的补偿项破坏另一个已经有效的补偿项。
