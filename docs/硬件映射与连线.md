# 硬件映射与连线

最后核对：2026-08-01

## 1. 关节与电机

系统使用 21 路磁编码器和 27 个舵机。当前映射：

| 手指/关节 | 电机 |
| --- | --- |
| J00 | M00/M01（双腱） |
| J01/J02/J03 | M02/M03/M04 |
| J04 | M05/M06（双腱） |
| J05/J06/J07 | M07/M08/M09 |
| J08 | M10/M11（双腱） |
| J09/J10/J11 | M12/M13/M14 |
| J12 | M15/M16（双腱） |
| J13/J14/J15 | M17/M18/M19 |
| J16 | M20/M21（双腱） |
| J17/J18/J19 | M22/M23/M24 |
| J20 | M25/M26（双腱） |

双腱组的第二执行器 tendon sign 与第一执行器相反。Mxx 是软件扁平通道，物理 servo ID 当前也等于 Mxx；不要把“当前相等”写成协议永久保证，bus/id 的权威仍是 HardwareMap。

四路舵机 UART 均为 1 Mbit/s：bus0 为 M00~M07；bus1 为 M08、M10~M14；bus2 为 M09、M15~M19；bus3 为 M20~M26。四路并行是为了缩短 27 路同步读写的总阻塞时间，并把单总线故障限制在较小范围。

## 2. P4 引脚

| 功能 | 引脚 |
| --- | --- |
| Servo bus0 RX/TX | GPIO21 / GPIO20 |
| Servo bus1 RX/TX | GPIO23 / GPIO22 |
| Servo bus2 RX/TX | GPIO27 / GPIO26 |
| Servo bus3 RX/TX | GPIO33 / GPIO32 |
| CAN TX/RX | GPIO47 / GPIO48 |

接线时 RX/TX 以 P4 视角命名；P4 TX 接外设 RX，P4 RX 接外设 TX。四路 UART 均要共地，并确认电平与供电域。总线通但某一电机离线时，先核对 bus 与 ID，不要只扫描全部 ID 后修改 HardwareMap。

## 3. S3 磁编 SPI

| 信号 | GPIO/参数 |
| --- | --- |
| MISO/MOSI/SCLK/CS | 47 / 38 / 9 / 7 |
| 频率 | 10 MHz |
| SPI mode | Mode 1 |

默认 138 板为 CS demux：逻辑组 `group0~4` 对应 `J00~J03、J04~J07、J08~J11、J12~J15、J16~J20`，即小指、无名指、中指、食指、拇指；MUX channel 为 `{4,3,2,1,0}`。

临时 151 MISO-mux 路径保持同一逻辑手指顺序，但 board channel 为 `{7,6,5,3,4}`。修改 `ENC_HW_MODE` 后必须同时验证 selector、SPI mode、错误寄存器读取和 21 路 UI 索引，不能只看 ENC 总状态灯。

AS5047P 返回 16 bit word，含 parity/error flag 和 14 bit angle。raw=0 是合法零点，不能当作断线；只有协议错误、诊断失败或连接状态明确为 `0xFFFF` 才应标失效。

## 4. S3 触觉 SPI

| 信号 | GPIO/参数 |
| --- | --- |
| MISO/MOSI/SCLK | 21 / 10 / 8 |
| CS_A/CS_B | 7 / 6 |
| group A/B/C | 13 / 14 / 17 |
| 频率 | 1 MHz |
| SPI mode | Mode 3 |

触觉逻辑组同样为 `G0=小指、G1=无名指、G2=中指、G3=食指、G4=拇指`，channel map 为 `{0,1,2,3,4}`。每组包含 3 片传感器，摘要为 `5×3×3=45 bytes`，全量为 1530 bytes。传感器响应使用 CRC8 查表校验；多路选择与磁编共享 selector 资源时由 `g_sensorSelectMutex` 串行化，避免两个 SPI 任务同时改变选通信号。

## 5. S3 CAN 与任务核对

S3 CAN TX/RX 为 GPIO48/GPIO1，Classic CAN 1 Mbit/s。编码器任务固定在 core1、优先级 10、周期 2 ms；触觉在 core0、优先级 5、周期 33 ms；CAN 在 core0、优先级 5、周期 4 ms；SysMgr 在 core1、优先级 1。

源码中 `TASK_ENC_CORE/TASK_TAC_CORE` 宏与 `SystemTasks.cpp` 当前 literal core 分配存在表述差异：实际创建代码以 `SystemTasks.cpp` 为准。后续应统一改为使用 config 常量，避免只改宏却没有改变运行任务。

## 6. ENC 指示灯不等于 21 路都有数据

上位机 ENC 绿色通常表示 P4 最近收到过完整且通过 CRC 的编码器批次，不一定表示 UI 当前查看的 Jxx 值可用。单路仍可能因为 parity/error flag、group mapping、active mask、Manual/Auto 映射或显示层索引而无读数。

排查时同时查看：S3 的 21 路 raw dump、`errorFlags/latchedErrors`、CAN 0x100~0x106 完整批次、P4 encoder raw `0x0B`、mapped angle validFlags，以及 desktop 当前选中的 index。详见[实机验证与故障排查](实机验证与故障排查.md)。

## 7. 改线后的最小验证

1. 断开舵机动力，只验证 S3 21 路 raw、parity 和 error code；
2. 单独验证 CAN batch sequence/CRC/timeout；
3. 逐总线扫描 P4 舵机，核对 Mxx→bus/id；
4. 只启用一个 active joint，确认正向/反向和双腱配对；
5. 重做 Manual/Auto 标定，确认 mappingSignature、产品指纹和 URDF contract 一致；
6. 最后才进行整手 RopeInit 和闭环。
