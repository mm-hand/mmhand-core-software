# 舵机、磁编与触觉连线总结

> 当前专项文档，最后核对：2026-08-01。当前为 21 关节/27 电机/4 路舵机 UART；磁编 Mode 1、触觉 Mode 3，逻辑顺序从小指到拇指。若正文与当前表冲突，以[硬件映射与连线](硬件映射与连线.md)及源码为准。

本文根据当前代码整理舵机、磁编码器和触觉传感器相关的连线与映射关系。若后续改线或改表，建议同步更新本文。

## 1. 手指、关节与编号

| 手指 | 关节范围 | 说明 |
|---|---|---|
| 小拇指 Pinky | J00-J03 | 四个单自由度关节，其中 J00 为双电机 |
| 无名指 Ring | J04-J07 | 四个单自由度关节，其中 J04 为双电机 |
| 中指 Middle | J08-J11 | 四个单自由度关节，其中 J08 为双电机 |
| 食指 Index | J12-J15 | 四个单自由度关节，其中 J12 为双电机 |
| 大拇指 Thumb | J16-J20 | 五个关节，其中 J16、J20 为双电机 |

大拇指当前舵机映射为：

| 大拇指关节 | 舵机 |
|---|---|
| J16 | M20 + M21 |
| J17 | M22 |
| J18 | M23 |
| J19 | M24 |
| J20 | M25 + M26 |

## 2. 舵机总线与 ID

当前舵机 ID 从 0 开始，且物理舵机 ID 与上位机/代码中的 `Mxx` 编号一致：

```text
servo id 0  -> M00
servo id 1  -> M01
...
servo id 26 -> M26
```

P4 侧总线分配如下：

| 电机范围 | P4 总线 | 舵机 ID |
|---|---:|---|
| M00-M07 | bus0 | id0-id7 |
| M08 | bus1 | id8 |
| M09 | bus2 | id9 |
| M10-M14 | bus1 | id10-id14 |
| M15-M19 | bus2 | id15-id19 |
| M20-M26 | bus3 | id20-id26 |

### 4.2 默认 138 板磁编映射

当前默认 `ENC_HW_MODE = ENC_HW_MODE_138_CS_DEMUX`。

代码中的逻辑组顺序是 `group0..group4 = 小拇指..大拇指`，但物理 MUX 通道是反向映射：

| 逻辑组 | 手指 | 关节范围 | MUX channel | 习惯称呼 |
|---|---|---|---:|---|
| group0 | 小拇指 | J00-J03 | 4 | SPI5 |
| group1 | 无名指 | J04-J07 | 3 | SPI4 |
| group2 | 中指 | J08-J11 | 2 | SPI3 |
| group3 | 食指 | J12-J15 | 1 | SPI2 |
| group4 | 大拇指 | J16-J20 | 0 | SPI1 |

对应代码：

```cpp
static constexpr uint8_t ENC_138_GROUP_CHANNEL_MAP[5] = {4, 3, 2, 1, 0};
```

### 4.3 151 板兼容映射

若编译时切到 `ENC_HW_MODE_151_MISO_MUX`，使用下面的板级通道：

| 逻辑组 | 手指 | 关节范围 | 151 channel |
|---|---|---|---:|
| group0 | 小拇指 | J00-J03 | 7 |
| group1 | 无名指 | J04-J07 | 6 |
| group2 | 中指 | J08-J11 | 5 |
| group3 | 食指 | J12-J15 | 3 |
| group4 | 大拇指 | J16-J20 | 4 |

对应代码：

```cpp
static constexpr uint8_t ENC_151_GROUP_CHANNEL_MAP[5] = {7, 6, 5, 3, 4};
```

## 5. 触觉传感器连线与 SPI/MUX 映射

### 5.1 S3 触觉 SPI 引脚

| 信号 | GPIO |
|---|---:|
| TAC MISO | 21 |
| TAC MOSI | 10 |
| TAC SCLK | 8 |
| TAC CS_A | 7 |
| TAC CS_B | 6 |
| TAC GRP_A | 13 |
| TAC GRP_B | 14 |
| TAC GRP_C | 17 |
| TAC GRP_EN | -1，未使用 |

### 5.2 当前代码实际触觉组顺序

当前触觉代码实际使用：

```cpp
static constexpr uint8_t TACTILE_GROUP_CHANNEL_MAP[TACTILE_GROUP_NUM] = {0, 1, 2, 3, 4};
```

当前 S3 与上位机按以下逻辑顺序解释触觉原始组：

```text
G0 = pinky  / SPI5
G1 = ring   / SPI4
G2 = middle / SPI3
G3 = index  / SPI2
G4 = thumb  / SPI1
```

也就是说，触觉当前与磁编的物理手指对应关系一致：

| 物理 SPI | 触觉组 | 手指 |
|---|---|---|
| SPI1 | G4 | 大拇指 |
| SPI2 | G3 | 食指 |
| SPI3 | G2 | 中指 |
| SPI4 | G1 | 无名指 |
| SPI5 | G0 | 小拇指 |

### 5.3 触觉每组 3 个传感器

每个触觉组内有 3 个触觉传感器：

| 组内传感器 | 选择位 | 代码含义 |
|---|---:|---|
| sensor0 | `0x03` | DP / fingertip，指尖 |
| sensor1 | `0x02` | IP / middle phalanx，中节 |
| sensor2 | `0x01` | CP / proximal phalanx，近节 |

触觉读取选择模式由 `HalTactile.cpp` 中的 `makeSelectorPattern(group, sensorBits)` 生成：

```cpp
selector = (TACTILE_GROUP_CHANNEL_MAP[group] << 2) | sensorBits;
```

## 6. 磁编与触觉组号的关键区别

当前代码中，磁编和触觉虽然物理上都遵循：

```text
SPI1=大拇指, SPI2=食指, SPI3=中指, SPI4=无名指, SPI5=小拇指
```

但两者的逻辑组号方向不同：

| 系统 | G/group0 对应 | G/group4 对应 | 原因 |
---|---|---|---|
| 磁编 | 小拇指 | 大拇指 | 关节编号是 J00 从小拇指开始 |
| 触觉 | 大拇指 | 小拇指 | 上位机触觉模型按 thumb,index,middle,ring,pinky 显示 |

因此不要把“磁编 group0”和“触觉 G0”直接看成同一根手指。看物理连线时，应优先看 SPI1..SPI5；看数据数组时，应按各自模块的逻辑顺序解释。

## 7. 当前需要注意的注释冲突

`ESP32-S3/System/src/config/Config.h` 中触觉映射附近仍有旧注释写着：

```text
G0=pinky(SPI5), ..., G4=thumb(SPI1)
```

但当前实际代码值是 `{0, 1, 2, 3, 4}`，并且 `HalTactile.cpp` 与 `desktop/core/comm_layer.py` 当前按：

```text
G0=thumb(SPI1), ..., G4=pinky(SPI5)
```

理解和显示。后续若要避免误读，建议把 `Config.h` 的旧注释同步改掉。

## 8. 改线后的检查顺序

1. 先单独确认 S3 磁编串口打印：每个 SPI 组的 raw 是否对应正确手指。
2. 再看 P4 CAN 接收日志：`firstRaw`、`encSnap`、`tsAge` 是否稳定。
3. 打开上位机 Joint Channels，确认 J00-J20 raw/current 是否落到对应手指。
4. 打开触觉窗口，连接 S3 触觉串口，逐个按压 SPI1..SPI5 对应手指，确认 UI 上对应区域响应。
5. 舵机直控模式下逐个点选 M00-M26，小幅动作确认电机 ID 与 M 编号一致。
6. 映射或物理接线变更后，必须重新标定，再进入负反馈控制。
