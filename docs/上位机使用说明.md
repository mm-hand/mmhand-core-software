## 1. 文档目的

本文面向 MMHand 上位机的操作人员，说明：

- 每个窗口、按钮、表格和状态显示的作用；
- 首次使用、日常启动、标定、控制、遥操、记录和回放的正确顺序；
- 哪些操作会移动舵机、清除数据或要求重新标定；
- 出现离线、Multi-turn Unknown、Calibration Failed、Overload 或 Collision Hold 时如何处理。

本文只描述用户操作。控制算法、协议和固件实现参见项目中的技术文档。

### 1.1 首次安装与图标启动（Windows）

维护人员先安装 Python、`desktop/requirements.txt` 中的依赖及所需 ROS2 环境。
在项目根目录执行一次以下命令，路径替换为本机实际位置：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/create_desktop_shortcut.ps1 -PythonPath "C:\PythonEnv\python.exe" -RosSetup "C:\ros2\local_setup.bat"
```

- `PythonPath` 必须是已安装上位机依赖、且与 ROS2 Python 包兼容的解释器。
- 不需要额外初始化 ROS2 环境时可省略 `-RosSetup`。脚本不会安装 ROS2 或启动外部遥操/IK 节点。
- 安装后双击桌面 **MMHand** 图标即可；命令窗口默认最小化，不需要输入命令。
- Python 环境、ROS2 安装或项目目录搬移后，重新生成快捷方式。
- 快捷方式不修改系统环境变量。直接双击 `start_mmhand.cmd` 即可：优先使用显式配置的 `MMHAND_PYTHON`，否则依次查找项目 `.venv`、已激活虚拟环境、Windows `py -3` 和 PATH 中的 `python`。不要求事先创建 `.venv`。
- 自动查找到的 Python 仍需安装上位机依赖；多个 Python 环境并存时，可用快捷方式固定正确解释器。不会自动安装软件或修改系统 Python。
- ROS2 接收桥默认开启，但运动仍需用户明确执行 `ENABLE` 和 `ROS2 INPUT`。
- ROS2 桥加载失败会弹出 **ROS2 unavailable**，串口手动操作仍可使用。
- 路径/依赖错误导致启动失败时，查看任务栏中的命令窗口，错误会保留供排查。

命令行入口保持不变（使用已准备好依赖和 ROS2 环境的终端）：

```powershell
python -m desktop ui
python -m desktop ui --no-ros2
python -m desktop cli
```

## 2. 安全须知

> **运动风险**：`ENABLE`、`Calibrate`、`Release Rope`、关节/舵机 `Send`、测试按钮和 Replay 都可能驱动机械结构。

1. 上电前确认手部机构无遮挡，绳路、连接器和舵机固定可靠。
2. 首次动作使用单关节或单手指 `Control Set`，确认方向后再扩大范围。
3. 操作时保持可以立即点击 `E-STOP`；键盘 `Esc` 也会触发停止。
4. `Release Rope` 会重置全部舵机圈数、清除多圈锚点并使 Auto/LUT/ABS Limit 失效，完成后必须重新自动标定。
5. `Clear Fault` 只应在实际故障原因排除后使用；清除后系统仍需重新 `ENABLE`。
6. `Motor Channels` 是舵机绝对位置直控，绕过关节角负反馈，建议只用于维护和受控调试。

### 2.1 操作风险分级

| 等级 | 操作 | 影响 |
| --- | --- | --- |
| 低 | `Refresh`、查看状态、打开 Plot/Hand Pose/Task Runtime | 不主动产生运动 |
| 中 | `Pause`、`Load Calibration...`、`Write Modified` | 改变运行状态或配置，不应在运动中执行 |
| 高 | `ENABLE`、关节/电机 `Send`、各类 Test、Replay | 可能立即驱动选中执行器 |
| 很高 | `Calibrate`、`Release Rope`、`E-STOP`、`Clear Manual` | 可能大范围运动、锁存停止或使标定失效 |

## 4. 推荐使用顺序

### 4.1 日常启动（已有有效标定）

1. 给机械手、P4、S3 和舵机供电，确认急停条件已解除。
2. 启动上位机。
3. 在 `Port` 中选择 P4 主控串口。选择后会自动连接；`Refresh` 只刷新串口列表。
4. 等待连接灯变绿，并等待启动恢复流程结束。
5. 检查顶部状态：
   - `System` 不应显示通信故障或阻断故障；
   - `Calibration` 应显示 `Success` 或可用状态；
   - `Overload` 应为 `Normal`；
   - `Multi-turn` 应为 `Known`；
   - `Status Age` 应稳定在绿色范围。
6. 进入 `Mode > Manual`，打开 `Joint Channels`。
7. 选择尽可能小的 `Control Set`，确认对应关节和电机在线。
8. 点击 `ENABLE`，等待 `System: Ready` 或 `System: Feedback Control`。
9. 使用关节滑条、`Send`、测试页或授权后的 ROS2 输入进行控制。
10. 临时停止使用 `Pause`；发生异常立即使用 `E-STOP`。

> **图片占位 图 4-1：日常启动成功状态**  
> 建议截图：连接灯为绿色、Multi-turn Known、Overload Normal、Control Set 已选择。  
> 建议文件名：`images/desktop_user_guide/02-routine-start-ready.png`

### 4.2 首次装机或标定已失效

1. 连接 P4，并确认所需舵机、磁编码器和 BUS 路由在线。
2. 在 `Device Check` 中采集每个关节的 `Manual Min` 与 `Manual Max`。
3. 点击 `Write Modified`，等待 ACK、读回、CRC 和桌面 JSON 全部验证成功。
4. 切换到 `Joint Channels`，选择要标定的 `Control Set`。
5. 点击 `Calibrate` 并确认安全提示。
6. 等待自动标定和后续 Rope Initialization 完成，不在中途切换模式或发送其他目标。
7. 确认 `Calibration: Success`、`Multi-turn: Known`，系统进入 `Ready`。
8. 从单关节小范围动作开始验证方向和行程。

### 4.3 使用已有标定文件恢复

1. 连接正确的 P4，保持系统不在控制、标定或 Rope Initialization 运动状态。
2. 点击 `Load Calibration...`。
3. 选择匹配当前机械、舵机 ID、映射和产品指纹的 `.mmcal.json`。
4. 阅读确认框后继续，等待 Manual、Auto/LUT、ABS Limit 和多圈恢复完成。
5. 只有顶部状态恢复正常后才点击 `ENABLE`。

## 6. 顶部状态条

### 6.1 状态项说明

| 状态项 | 常见显示 | 含义与处理 |
| --- | --- | --- |
| `System` | `Uncontrollable` | 当前没有运动控制权；故障清除后或启动初期可能出现 |
| `System` | `Idle` | 已通信但尚未进入可控工作区 |
| `System` | `Ready` | 标定、反馈和工作区满足控制条件 |
| `System` | `Feedback Control` | 正在执行关节角负反馈控制 |
| `System` | `Direct Control` | 正在执行电机 ABS 直控 |
| `System` | `Calibrating` | 自动标定正在运行 |
| `System` | `Rope Initialization` | 正在回到标定后的可控工作区 |
| `System` | `Paused` | 输出暂停，目标缓存保留 |
| `System` | `Recovery Required` | 需要恢复多圈、标定或设备状态 |
| `Calibration` | `Idle/Pending/Running` | 未运行、等待开始或正在标定 |
| `Calibration` | `Success/Warning/Failed` | 标定成功、可用但有警告、标定失败 |
| `Overload` | `Normal` | 当前没有舵机过载 |
| `Overload` | `Mxx (load)` / `n motors` | 一个或多个舵机达到过载条件；点击 `Details` 查看全部 |
| `Collision` | `Idle` | 尚未进入碰撞监测窗口 |
| `Collision` | `Monitoring Jxx` | 对列出的关节进行碰撞监测 |
| `Collision` | `Hold Jxx` | 对列出的关节执行 ABS Hold |
| `Multi-turn` | `Known` | 当前 Control Set 内全部舵机多圈坐标可信 |
| `Multi-turn` | `Unknown Mxx` | 列出的舵机多圈未知，控制会被阻止 |
| `Status Age` | `<200 ms` | 正常、绿色 |
| `Status Age` | `200-999 ms` | 通信变慢、黄色，应检查负载和串口 |
| `Status Age` | `>=1 s` | 状态过期、红色，不应继续控制 |
| `Details` | 可点击/不可点击 | 显示全部活动碰撞、系统故障、标定诊断和近期安全事件 |

| 颜色 | 含义 |

| 黄色 | 延迟、等待或非阻断警告，需要关注 |
| 红色 | 故障、状态过期、过载或控制阻断 |
| 灰色 | 未连接、尚无数据或该项不适用 |

## 7. Device 控制按钮

| 按钮 | 作用 | 使用时机 | 后续状态 |
| --- | --- | --- | --- |
| `ENABLE` | 按当前模式和 Control Set 申请控制权 | 连接、恢复、路由和标定检查完成后 | Joint 模式进入 Ready/Feedback；Motor 模式保持当前 ABS |
| `E-STOP` | 立即请求锁存式停止并取消测试、Replay 和 ROS2 目标 | 任何危险或不可预期运动 | 必须排除原因并重新 `ENABLE` |
| `Pause` | 暂停输出但保留当前目标缓存 | 临时停机、希望之后继续当前目标 | 再次 `ENABLE` 可恢复 |
| `ROS2 INPUT` | 授权外部 ROS2 关节目标 | 遥操前，且已完成普通 Enable 条件检查 | 开启时显示 `ROS2 INPUT ON` |
| `Calibrate` | 标定当前 Joint Channels 中选中的 active joints | Manual 数据完整，系统停止且机械安全 | 自动标定后执行 Rope Initialization |
| `Clear Fault` | 清除锁存保护、故障和旧命令状态 | 实际原因已排除后 | 回到 Uncontrollable，需重新 Enable |

| 按钮 | 作用 | 重要限制 |
| --- | --- | --- |
| `Load Calibration...` | 从外部或历史 `.mmcal.json` 恢复标定 | 机械、ID、映射和产品必须匹配；运动中禁止加载 |

## 10. Device Check 页面

### 10.1 页面用途

用于查看和维护 21 路磁编码器 Manual 端点、Auto 标定结果以及 P4 RAM/桌面 JSON 一致性。

### 10.2 顶部按钮

| 按钮 | 作用 |
| --- | --- |
| `Release Rope` | 全 27 舵机 Reset Zero、清除多圈锚点、失效 Auto/LUT/ABS Limit，并放绳 1500 counts |
| `Write Modified` | 只写入已修改的 Manual 行，并执行 ACK、读回、CRC 和 JSON 验证 |
| `Clear Manual` | 清除全部 21 路 Manual 端点；之后标定和负反馈均被阻止 |

### 10.3 表格列

| 列 | 含义 |
| --- | --- |
| `Status` | 当前关节 Manual/Auto/工作区是否可用 |
| `Joint` | 关节编号 J00-J20；悬停可查看关节名称 |
| `Raw Dir` | 从 Manual Min 到 Manual Max 时 raw 增加或减小的方向 |
| `Current Raw` | 当前 14-bit 磁编码器原始值 |
| `Manual Min/Max` | 人工确认的机械端点 raw |
| `Use Raw` / `Set` | 将当前 raw 复制到对应 Manual Min 或 Max |
| `Manual Span` | 沿 Raw Dir 从 Manual Min 到 Manual Max 的有效跨度 |
| `Auto Min/Max` | 自动标定得到的实际工作端点 |
| `URDF Span (Enc)` | URDF 角度范围换算得到的理论磁编跨度 |
| `URDF Min/Max` | 当前模型规定的关节角范围 |
| `Current Min` | 本次 Auto 结果对应的当前可用最小角度 |
| `RAM/JSON` | P4 RAM 与桌面标定 JSON 的一致性状态 |

### 10.4 Manual 端点采集步骤

1. 将目标关节安全移动到定义中的 `Manual Min` 姿态。
2. 确认 `Current Raw` 稳定，点击该行左侧 `Set`。
3. 将关节移动到 `Manual Max` 姿态，点击右侧 `Set`。
4. 检查 `Raw Dir` 与 `Manual Span` 是否合理。
5. 点击 `Write Modified`，等待底部状态栏明确显示验证成功。
6. 对其余需要标定的关节重复以上步骤。

## 12. Motor Channels 页面

## 13. Test 页面

### 13.1 Pose Test

| 按钮 | 作用 |
| --- | --- |
| `Open Pose` | 向全部 21 关节发送 0 deg |
| `Fist Pose` | 向 active joints 发送配置中的握拳姿态 |

### 13.2 Joint Sine Test

每行可设置 `Joint`、`Min(deg)`、`Max(deg)`、`Freq(Hz)` 和 `Phase(deg)`。`Initial Hold(s)` 用于测试前保持初始目标。

| 按钮 | 作用 |
| --- | --- |
| `Start Test` | 启动当前配置的多关节正弦测试 |
| `Stop Test` | 停止正弦测试，不等同于 E-STOP |

### 13.3 Feedforward Test

设置单个 `Joint`、逗号分隔的 `Targets(deg)` 和 `Step Time(s)`，使用 `Start Feedforward Test` / `Stop Feedforward Test` 控制测试。

### 13.4 Triangle Wave Test

## 16. Save Data 与输出文件

### 16.1 基础记录

`Save Data` 默认勾选。P4 连接后，上位机按约 50 ms 周期保存运动状态；P4 内部控制仍按自身高频周期运行，CSV 采样频率不等于控制频率。

基础记录应说明以下内容：

- 会话目录与文件命名规则：`[待填写实际路径示例]`
- 关节目标、实际角度和有效位；
- 舵机 ABS、raw、load 与 command；
- P4 时间戳和主机接收时间；
- ACK、安全事件和控制 trace 的关联方式。

### 16.2 触觉全量记录

启用触觉全量表后，逐 taxel 保存：

`finger / sensor / row / col / Fx / Fy / Fz / force_mag`

这些字段可以按 `finger + sensor + row + col` 重建完整触点阵列。

## 17. 标定状态、警告与失败诊断

### 17.1 标定成功

- `Calibration: Success` 表示本轮标定结果已提交。
- 标定结束后仍需等待 Rope Initialization 和系统进入 Ready。
- 分批标定时，已成功关节应保留，后续只更新本轮关节。

### 17.2 标定警告

`Calibration: Warning` 表示结果仍可使用，但存在装配端点偏差等非阻断问题。将鼠标悬停在状态项或点击 `Details` 查看涉及关节。

### 17.3 标定失败

失败弹窗和 `Details` 应显示：

- 唯一 reason 标题；
- 失败阶段；
- 关节 Jxx 和舵机 Mxx；
- reason 对应的命名数据字段；
- 本轮 completed/failed joint mask；
- 用户处理建议。

记录弹窗、底部状态栏和同一时间段固件日志后，再清除故障。不要只根据 `reason` 数字猜测原因。

## 18. 常见故障处理

| 现象 | 先检查 | 建议操作 |
| --- | --- | --- |
| 串口打开但连接灯不绿 | `System`、Status Age、底部状态栏、端口是否为 P4 | Refresh 后重选端口，确认固件协议和波特率 |
| `Multi-turn: Unknown Mxx` | 对应舵机在线、SavedRaw/AbsNow、标定文件和产品指纹 | 等待自动恢复；失败时只重标受影响关节 |
| `Calibration: Not Calibrated` | Manual、Auto/LUT、RAM/JSON | 加载匹配标定文件或重新标定 |
| `Overload` | Details 中 Mxx 和触发 load | E-STOP、卸载外力、检查绳路，之后 Clear Fault |
| `Collision: Hold Jxx` | Details 中目标方向、误差和 ABS 进度 | 检查机械碰撞、绳路和反馈后解除 |
| `Status Age` 变黄/红 | CPU、串口占用、Task Runtime、日志量 | 停止测试，减少诊断负载并检查 P4 通信 |
| Enable 按钮无动作 | 底部状态栏的 blocked 原因 | 按提示处理 offline、route、encoder、turn、calibration 或 scope |
| 触觉 `STALE/OFFLINE` | S3 端口、SPI 通道、Raw Data | 排除端口占用、CRC、供电、MISO/SCLK/CS 与传感器硬件 |
