# 控制算法与标定

坐标逻辑最后核对：2026-10-10

## 1. 控制对象与坐标

系统有 21 个关节、27 个电机，其中 J00、J04、J08、J12、J16、J20 是对抗双腱关节。控制链路涉及三种量：

- 磁编 raw：14 bit，范围 0~16383，`0xFFFF` 表示断连；
- 关节角：由 Manual/Auto V3、URDF 限位和环形方向映射得到，单位 degree；
- 电机 ABS：P4 控制坐标与飞特舵机实际多圈坐标一致。

控制和标定直接使用实际 ABS，目标检查硬件范围后下发。舵机单独掉电后，P4 根据可信 ABS/raw 锚点计算最近圈目标，以 `0x0B` 将舵机实际坐标恢复到该值，读回确认后继续使用原 LUT 和限位。没有可信锚点或恢复失败时保持 Unknown。

## 2. 单腱 PID

单腱关节由一个电机收/放绳。当前 P4 是关节角外环，飞特舵机内部位置环是内环：

```text
关节目标角 - 磁编反馈角 → 离散 PID → 电机 logical ABS 增量 → 舵机内部位置环
```

当前参数：`Kp=5.7`、`Ki=0`、`Kd=0`、积分限幅 100、输出限幅 600 counts，周期 10 ms。虽然实现保留完整 PID 状态，但目前本质是带输出限幅的 P 控制；简历或评审中不能写成“已完成 PID 三参数整定”。

选择这种结构的原因：磁编直接反映关节实际角度，可以补偿绳索弹性、装配误差和舵机位置与关节角之间的非线性；输出增量再经标定 LUT 和用户锁定限位裁剪，可避免只凭线性比例把电机拉出实测工作区。LUT 无效时保持当前位置，而不是猜测映射继续运动。

## 3. 对抗双腱控制

双腱不能简单复用“一个 PID 输出取反发给第二台电机”。两根绳的零点、有效行程、预紧量和弹性不同，同一 counts 不代表同一关节角。

当前做法是：

1. 使用自动标定得到的双路 LUT，分别把 `qRef` 和 `qFb` 投影到两台电机的标定位置域；
2. 每台电机基于自己的模型位置误差计算小幅修正；
3. 主/副执行器按 HardwareMap 中的 tendon sign 运动，副侧是相反方向；
4. 分别裁剪到各自 LUT 包络、用户锁定范围、会话 logical range 和硬件范围；
5. 两台电机必须同时在线、多圈状态满足策略且标定通道匹配，否则两侧一起 hold。

当前参数：`Kp=0.60`、`Ki=0`、`Kd=0`、D 项限幅 100 counts、速度低通时间常数 50 ms。实现使用滤波后的速度误差作为 D 项输入，目的是将来启用 Kd 时减小目标阶跃造成的 derivative kick；但当前 Kd 为 0，不能夸大为已启用速度闭环。

这种设计的收益是每根腱都在自己的实测坐标内受控，保持对抗关系，并把“某一侧失联仍继续拉另一侧”的故障变成明确拒绝。

## 4. 完成判定、过载与碰撞保护

| 功能 | 当前参数 | 含义 |
| --- | --- | --- |
| 直接位置完成 | 误差 ≤40 counts，连续 5 个周期 | 防止单帧抖动误报到位 |
| 反馈闭环完成 | 误差 ≤0.5°，连续 10 个周期 | 约 100 ms 稳定后才完成 |
| 反馈运行超时 | 8000 ms | 长时间无法收敛交回状态机处理 |
| 直接模式过载 | load magnitude ≥800，连续 20 周期 | 硬故障锁存 |
| 反馈模式过载 | load magnitude ≥2000，连续 20 周期 | 与碰撞判断分开 |
| 标定过载 | load magnitude ≥800 | 标定立即失败，防止继续拉绳 |

碰撞检测不使用单一负载阈值。它观察“控制仍在向目标推动，但关节角在一段时间内没有足够进展”：误差至少 4° 才武装，200 ms 速度窗内达到 8°/s 后开始观察，400 ms 内进展小于 0.4° 则进入 hold；目标向退让方向回撤 1° 后释放。这样能区分高静态预紧与真正被阻挡，也不依赖不同舵机负载标度完全一致。

## 5. 自动标定为什么使用状态机

自动标定包含等待反馈、紧绳找端点、松绳前同步、反向释放找机械端、采样 LUT、校验和提交。任何阶段都可能遇到热插拔、过载、反馈过期或 owner 丢失。显式状态和上下文让每个 20 ms step 可取消、可诊断，不需要在高优先级任务中长时间阻塞。

开始机械动作前会检查：舵机反馈最大年龄 500 ms、磁编样本最大年龄 300 ms、首帧等待 1200 ms；热插拔恢复最多 5000 ms，并要求 3 个连续稳定样本；多圈可信提交时限 1000 ms。

## 6. 机械限位判定阈值

以下是当前自动标定中与“松绳/机械端点”直接有关的全部主要阈值，事实源为 `CalibrationConfig.h` 和 `defaultAutoCalibrationParams()`：

| 阈值 | 当前值 | 参与的判定 |
| --- | ---: | --- |
| 状态机 loop | 20 ms | 每次推进/采样间隔 |
| 观察窗口 `windowMs` | 200 ms | 比较窗口首尾舵机和磁编变化 |
| 舵机仍在运动 | 窗口 ABS 变化 ≥50 counts | 证明命令确实在继续放绳/收绳，避免把电机没动误判成机械端 |
| 关节角停稳 | 窗口角变化 ≤0.75° | 磁编已经基本不再跟随 |
| 停稳连续样本 | 2 个观察窗口 | 抑制单次采样噪声，等价于至少约 400 ms 的重复确认 |
| 反向最小跟随行程 | ≥12° | 先确认关节确实随松绳动作走过有效行程，避免起点即抖动被判为端点 |
| 单腱最大释放量 | 8192 counts（2 圈） | 即使未找到端点也不得无限放绳 |
| 松绳前目标误差 | ≤40 counts | 收紧段残余轨迹已追上保持目标 |
| 松绳前相邻 ABS 稳定 | ≤20 counts/200 ms | 防止尚未停稳就反向切换 |
| 松绳前稳定样本 | 2 | 目标到位且 ABS 停稳连续确认 |
| 最小有效总行程 | ≥10° | 过短行程不生成可信标定 |
| 最大有效总行程 | ≤359° | 避免环形方向歧义 |
| 近整圈 span 拒绝 | ≥15360 counts | 14 bit 数据接近整圈时视为 wrap/端点异常 |

单腱松端的最终成立条件是：`servoStillReleasing && angleStallStable>=2 && releaseTravel>=12°`。负载不是松端成立条件；它主要用于紧端发现和 800 的硬过载保护。因此如果磁编断线、方向映射错误或数值冻结，算法可能表现为“舵机在放但很快报端点/行程无效”，诊断时必须同时看窗口 ABS、窗口角度、累计角度和 fresh/valid 标志。

双腱反向交换阶段还要求两台电机在 200 ms 窗口内各移动至少 50 counts，并已获得至少 12° 磁编跟随；最终紧侧同时达到对应 load 阈值。当前主要负载阈值：主腱首次紧端 190、副腱预紧 190、副腱最终 A 姿态 250、普通双腱最终主腱 120、辅助工作空间紧绳 190。双腱准备阶段释放量和工作空间姿态切换释放量均为 3200 counts，姿态缓存复用容差为 60 counts。

## 7. 标定结果与安全范围

- 标定 LUT 每 5° 采一个等角度样本；
- 单腱完成后以实测 LUT 包络登记电机 logical ABS 范围，再给紧端增加 500 counts 保护余量；
- 通用自动标定搜索窗最多 5 圈（20480 counts）；
- `kServoZeroPullCounts=500` 用于 ABS Limit Max 相对紧端的安全余量语义；
- 结果必须与当前 Manual 条目 CRC、URDF 配置 CRC 和 mapping version 匹配，任一改变都会使旧 Auto 结果失效。

## 8. RopeInit 的真实作用

RopeInit 不是自动标定，也不是“拉到负载阈值”。它在 Manual NVS、Auto V3、URDF/mapping、反馈、在线状态和 fault 全部满足时，只把低于 Auto Min 工作区的 active joints 带回可控区：

- 周期 50 ms，总超时 8000 ms，反馈最大年龄 500 ms；
- 只有 `outsideCounts < -24` 的关节才运动；
- 单腱或主执行器每帧收绳 60 counts；双腱副执行器同时放绳 30 counts；
- 所有关节连续 3 帧进入工作区后完成；
- 状态是 `ROPE_INIT_RUNNING`，owner 为 `CALIBRATION`，`controlEnabled=0`。

采用慢速小步和主收/副放，是为了在未知工作区外减少突然增加对抗张力的风险。RopeInit 不覆盖标定数据，完成后由状态机重新判定是否 READY。

## 9. 调参原则

- 先记录窗口内 `ABS delta / angle delta / total travel / load / fresh`，再改阈值；
- 不能只降低角停稳阈值来掩盖磁编丢帧，也不能只提高负载阈值来绕过绳路卡滞；
- 启用 Ki/Kd 前先验证输出限幅、anti-windup、采样 dt 和目标阶跃；
- 双腱参数必须成对测试，记录两侧 logical ABS、load、LUT 位置和关节角；
- 标定改动先在单关节 active scope、低风险工装下验证，最后再整手回归。
