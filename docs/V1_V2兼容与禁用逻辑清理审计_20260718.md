# V1/V2 兼容与禁用逻辑清理审计

> 文档状态（2026-08-01）：兼容性专项审计，保留历史判断依据。当前新数据路径以 Auto V3、Manual 条目 CRC、URDF config CRC 和 mapping version 为准；任何删除 V1/V2 读取路径的动作仍需先证明现场 NVS/快照已经迁移。

> 执行状态（2026-07-18）：A01-A11 已完成删除并通过全文引用核查；B/C 组仍为后续迁移建议，未在本次改动中删除。

## 1. 范围与结论

审计范围：当前 `cl` 分支的 `ESP32-P4/ServoBoardMain/src` 和 `desktop` 源码；不包含 `ESP32-P4Test*`、`wuji_hand_ws/build`、`wuji_hand_ws/install`、`wuji_hand_ws/log` 等测试或生成目录。

当前正式系统已经固定为：**21 个关节、27 个舵机、双腱拓扑、Manual + Auto v3 标定、签名模式的 P4 状态包、`urdf_deg` 新链路**。仓库仍保留了三类旧逻辑：

1. 已经在默认编译配置下完全不可达的调试/启动实验代码；
2. P4 和上位机仍能解析旧 V1/V2 包，但接收后又拒绝使用的“假兼容”；
3. 旧 Flash、旧 P4 固件、旧 MANUS/IK 生产者的迁移兼容。这一类不能直接删，需先决定是否放弃迁移能力。

本次是**只读审计**，没有删除协议或控制逻辑。下表给出清理优先级；建议先完成 A 组，再在所有手均已升级/重新标定后完成 B 组，C 组需要先迁移遥操作输入。

## 3. B 组：假 V1/V2 兼容，可在统一升级后删除

### B01：Calib Load V1/V2 载荷长度

位置：

- `UpperCommProtocol.h:85-91`
- `UpperCommTask.cpp:1477-1580,1977-1984`
- `desktop/core/protocol.py:465-590`

现状：P4 RX 预检查仍接受 54 字节旧版、扩展版和 V2 长度；但真正进入 `CMD_CALIB_LOAD_JOINT` 后，任何小于 V3 的载荷都会立即返回 `PROTO_ACK_STATUS_LEGACY_SNAPSHOT_REJECTED`。上位机构包也只允许 `mappingVersion == 3`。

结论：这是不产生任何可用兼容结果的冗余入口。可改为：

```text
P4：CMD_CALIB_LOAD_JOINT 仅接受 kCalibLoadJointV3PayloadBytes
Desktop：parse_joint_calib_snapshot_packet() 仅解析 V3 + 当前 warning 扩展字段
```

风险：删后不能再在当前 UI 中“查看”旧 P4 发出的 V1/V2 标定包；但它们本来就不能 Load 或进入 READY。验收：最新 P4 的 21 个 v3 snapshot 可保存、Calib Load、CRC 回读均成功。

### B02：旧 System Status、Motor Limit 包长度降级解析

位置：

- `desktop/core/protocol.py:252-386`：按 17/28/37/45/61/74/79/102/148 字节逐段降级；
- `desktop/core/protocol.py:388-410`：允许无 `lockedBitmap` 的旧 motor limit 包；
- P4 `UpperCommTask.cpp` 当前总是发送最新完整 System Status 和包含 `lockedBitmap` 的 limit 包。

建议：统一升级后将 desktop 解析改为严格校验当前最小长度。禁止短包被补零伪装为“某些状态未知”。

风险：旧 P4 将被明确标记为协议不兼容，不能再连接。优点是避免旧固件缺少 Manual/Auto/Turn 状态时被 UI 误判为可控。

### B03：Manual Flash V1 读取迁移

位置：

- `ESP32-P4/ServoBoardMain/src/persistence/ManualCalibrationNvsStore.cpp:19-49,100-110,151-168`
- `ManualCalibrationNvsStore.h:35-37`

现状：V1 是“21 路全部有效、没有 validMask”的旧 Flash 结构；当前代码读到 V1 后临时转换为 V2 RAM，但**不会回写为 V2**，所以每次上电都保留 V1 分支依赖。

这不是死代码：若现场有旧 V1 Manual Flash，立即删除将导致这些关节全部 Manual 缺失，必须重新手填后才能反馈/标定。

推荐迁移方案：

1. 保留 V1 读取一个固件版本；
2. 成功读取 V1 后立即调用现有 A/B `manualCalibrationNvsSave()` 回写 V2，并在日志中记录 `MANUAL_NVS_V1_MIGRATED`；
3. 确认所有手已写入 V2 后，下一个版本删除 `ManualCalibrationNvsSnapshotV1`、`snapshotV1ToV2()` 和 len 分支。

### B04：V1 单腱硬件 profile

位置：

- P4 `hardware/HardwareMap.h:6-10`、`HardwareMap.cpp:50-77`；
- desktop `core/protocol.py:190-194`、`ui_control_panels.py:565,3016,3210,3447,3628`；
- `MultiTurnNvsStore.cpp:65` 将 profile 放入 mapping signature。

现状：所有正式构建均固定 `HAND_PROFILE_V2`；V1 仅让 J00/J04/J08/J12 退化成单电机，并把 desktop 有效电机数退回 22。没有当前入口选择 V1 profile。

建议：固化 27 舵机/双腱拓扑，删除 `HAND_PROFILE_V1`、`#if HAND_PROFILE` 四组分支、desktop 的 V1 mask 选择和 UI 的 `(dual)` 条件。多圈 NVS 的 mapping signature 仍应保留一个固定“拓扑版本”字节，不能简单删去身份校验。

风险：旧 22 舵机 V1 手将不再可烧录此固件。这与当前 URDF、Manual/Auto v3、双腱控制的系统前提一致。

### B05：旧 JSON 快照“仅查看”路径

位置：

- `desktop/ui/ui_control_panels.py:3179-3364,3447,3628`
- `desktop/core/core_logic.py:1103-1150`
- `desktop/core/angle_mapping.py:333-351`

现状：UI 可读取 schema v1/v2 并显示“view-only/recalibration required”。当前 v3 才可发送 P4、进入 READY。

建议：将旧 JSON 快照移出运行目录到 `docs/migration/` 或转换脚本输入；运行时只加载 schema v3 + Manual CRC 一致的文件。这样 Calib Load 界面不会再出现不可执行的旧分支。

风险：用户不能直接在 UI 打开历史快照；历史分析应使用数据记录或独立迁移工具。

## 5. 推荐执行顺序

1. **第一提交：A01-A10。** 删除零调用/默认不可达代码与无效协议命令，先跑 P4 编译和 desktop 单元测试。
2. **第二提交：B01、B02、B05。** 将桌面和 P4 的运行时协议严格固定为当前 v3/完整状态包；发布说明中明确“旧 P4 不支持连接”。
3. **第三提交：B03。** 先做一次 V1 Manual Flash 自动迁移并观察现场日志；确认完成后再删除 V1 结构。
4. **第四提交：B04。** 固化双腱 27 舵机拓扑；会改变 multi-turn NVS signature，烧录后应按既有安全规则进入 Turn Unknown/恢复流程。
5. **第五提交：C 组中的 MANUS 迁移。** 将 MANUS 发布器改为 `urdf_deg` 后，再删除 `legacy_calibrated_deg`。这是遥操作语义变更，必须单独实机验收。

## 6. 删除后的最低验收集

```text
1. P4 完整编译、烧录并可连接 desktop。
2. Manual 单路写入/读回/CRC 校验；Auto 标定；Calib Load；Rope Init。
3. 双腱 J00/J04/J08/J12/J16/J20 的 READY 与负反馈。
4. 新设备、Turn Unknown、NVS 保存/恢复、E-STOP。
5. 当前 Wuji /raw_ik_target（urdf_deg）链路。
6. 若保留 MANUS：旧 MANUS 遥操作在迁移前的回归测试。
```

只有上述验证通过，才能把“代码变少”视为安全的去冗余，而不是把兼容问题转移成运行期故障。
