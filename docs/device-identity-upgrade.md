# 设备身份与锚点升级

设备 ID 来自 P4 芯片默认 eFuse MAC，编码为 64 位大端无符号整数；
Desktop 显示为 16 位大写十六进制字符串。读取失败为零，零不是有效身份。
这标识 P4 控制器；更换控制器后不会自动继承另一台控制器的运行锚点。

产品指纹业务负载为 36 字节，不含公共 P4 时间戳：

| 偏移 | 字段 | 长度 |
|---|---|---|
| 0 | 指纹语义版本 | 1 |
| 1 | 反馈坐标版本 | 1 |
| 2 | Manual 比例映射版本 | 1 |
| 3 | 上位协议版本 | 1 |
| 4 | 控制模型 CRC | 4 |
| 8 | 可视模型 CRC | 4 |
| 12 | 电机反馈拓扑 CRC | 4 |
| 16 | 参数 CRC | 4 |
| 20 | 固件源码 CRC | 4 |
| 24 | 结构提交 CRC | 4 |
| 28 | 设备 ID | 8 |

所有多字节字段使用大端编码。旧 28 字节指纹负载被拒绝。
协议版本由 `upper_protocol_schema.json` 生成到两端，当前为 2。
连接后发送双向契约握手：协议版本、控制模型 CRC 和反馈拓扑 CRC 必须匹配。
P4 返回执行确认后，Desktop 才允许运动与运动配置命令进入发送队列；
P4 在命令分派和状态准入处独立检查。握手不会自动授权 ROS 或启动运动。
不匹配返回独立的契约错误状态，并触发 P4 停止；失联后需要重新握手。
控制模型 CRC 包含关节绑定、方向和限位；改绑不会改变反馈拓扑 CRC。

运行数据位置：

```text
desktop/resources/config/device_state/<设备ID>/<URDF仓库内路径SHA256前16位>/multiturn_runtime.json
desktop/resources/config/device_state/<设备ID>/<URDF仓库内路径SHA256前16位>/calibration_bundle.mmcal.json
```

原始 URDF 路径来自生成来源记录，不包含开发机绝对路径或结构提交号。
文件身份还必须匹配设备 ID、完整 URDF 仓库内路径、指纹语义版本、
反馈坐标版本和拓扑 CRC。路径隔离不替代完整性与契约校验。

首次选择设备隔离目录时，旧全局锚点和标定 JSON 会备份为同目录下的
`<原文件名>.before-device-isolation.bak`，已有备份不会被覆盖。
旧文件保持原样，来源不明的锚点不自动恢复。
旧标定文件里的运行锚点只有明确匹配设备 ID 和 URDF 路径才参与恢复。

Manual 和 Auto/LUT 的活动文件也使用相同的设备目录。无有效身份时拒绝
保存与启动恢复；导入要求匹配设备、URDF 路径及模型/反馈契约。
Manual 元数据与端点在同一个原子写事务中保存，不能覆盖另一设备的有效文件。
设备切换撤销输入、取消标定事务并清除未提交 Manual 草稿。
当前模型契约变化保守拒绝恢复，关节改绑的局部失效仍待实现。
