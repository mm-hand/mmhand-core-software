## 4. 修改规则

### 协议

1. 先改 `upper_protocol_schema.json` 或对应协议事实源；
2. 运行生成器，检查 Python/C++ 生成物；
3. 同时更新 payload 长度、字节序、时间戳、sequence、超时和旧版兼容；
4. 增加截断、乱序、重复、CRC 错误和未知类型测试。

### 控制和安全

1. 参数只放对应 `config/*.h`，不要在实现中复制裸数字；
2. 控制目标必须经过 owner、scope、反馈、路由、范围和安全策略；
3. 不在 UI、parser 或 driver 中复制同一条安全规则；
4. 修改电机方向、LUT、Reset Zero 或多圈恢复时必须保留前后 CSV 和日志。

### 标定和 JSON

1. JSON 必须按 Jxx 增量合并，不能只保存最后一次标定；
2. Manual、Auto/LUT、ABS Limit、多圈锚点分别校验其身份和有效位；
3. P4 RAM 与桌面文件的写入要区分 ACK、提交完成和读回验证；
4. 任何 Reset Zero 后先失效旧坐标，只有新标定结果确认后才能产生新锚点。

## 5. 最小验证命令

```powershell
python -m desktop --help
python -m desktop ui --help
python -m desktop cli --help
python -m compileall -q desktop tests
pytest -q desktop/tests
python tools/generate_upper_protocol.py --check
python tools/check_desktop_architecture.py
```

P4/S3 的构建命令依赖实际 Arduino/ESP 工具链和板卡参数，必须把 IDE/CLI 输出
保存为交接证据，不在本文件虚构一个所有电脑都适用的命令。
