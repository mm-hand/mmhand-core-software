# 通信、硬件映射与触觉数据

最后核对：2026-09-10

## 1. 三条主要通信链路

| 链路 | 参数 | 作用 |
| --- | --- | --- |
| Desktop ↔ P4 | UART 921600 | 命令、状态、ACK、标定、诊断 |
| S3 ↔ P4 | Classic CAN 1 Mbit/s | 21 路磁编、错误详情、触觉摘要/全量 |
| P4 ↔ 舵机 | 4 路 UART，各 1 Mbit/s | 27 路飞特舵机扫描、同步读和目标发送 |

协议事实源是 `desktop/resources/config/upper_protocol_schema.json`；由
`tools/generate_upper_protocol.py` 生成 Python/C++ 常量。不要分别手改
`desktop/core/generated_upper_protocol.py` 和 P4 generated header。

## 2. P4 舵机 UART 引脚

当前 `BoardConfig.h`：

| BUS | P4 RX | P4 TX |
| --- | ---: | ---: |
| bus0 | GPIO21 | GPIO20 |
| bus1 | GPIO23 | GPIO22 |
| bus2 | GPIO27 | GPIO26 |
| bus3 | GPIO33 | GPIO32 |

P4 视角的 TX 要接外设 RX，RX 要接外设 TX，并且共地。Mxx 到 BUS/舵机 ID
由启动扫描产生唯一可控路由，不能把旧设备的静态 BUS 表直接当成当前事实。
排查单路离线时先看 `servo_route_bus`、冲突位图、BUS 负载和离线状态。

## 3. P4 与 S3 CAN

- P4 TWAI：TX GPIO47，RX GPIO48；
- S3 TWAI：TX GPIO48，RX GPIO1；
- 速率为 1 Mbit/s；
- S3 磁编批次使用 sequence、帧掩码和 CRC16 重组；
- 触觉摘要和全量使用独立 CAN ID、sequence、CRC 和重组超时。

CAN 单帧自带硬件 CRC，但它不能代替应用批次的 sequence/CRC。跨多帧批次必须
检查是否同一代、是否收齐、是否超时和 CRC 是否通过。

## 4. S3 磁编码器 SPI

当前 `ESP32-S3/System/src/config/Config.h` 和 `HalSensorSpi.cpp`：

| 信号 | GPIO | 参数 |
| --- | ---: | --- |
| MISO | 47 | |
| MOSI | 38 | |
| SCLK | 9 | 10 MHz |
| 模式 | | SPI Mode 1 |

21 路共用数据线，通过 138 CS demux 选择五组；逻辑顺序是 `G0` 小指、`G1`
无名指、`G2` 中指、`G3` 食指、`G4` 拇指，对应 J00-J20。AS5047P 返回
14 bit raw，并带 parity/error flag；raw 为 0 是合法值，不能以“等于 0”判定断线。

## 5. S3 触觉 SPI

| 信号 | GPIO | 参数 |
| --- | ---: | --- |
| MISO | 21 | |
| MOSI | 10 | |
| SCLK | 8 | 1 MHz |
| 模式 | | SPI Mode 3 |
| CS/组选择 | 7、6、13、14、17 | 由 pattern 选择 |

触觉每组当前包含 3 个传感器槽位，代码的摘要尺寸为 5×3×3=45 bytes；
S3 配置中的全量尺寸为 1530 bytes。触觉响应使用 CRC8，P4/S3 批次再用
应用层 CRC16。磁编和触觉选通信号访问由 S3 侧互斥保护。

## 6. 触觉数据等级

上位机 `HandModel.tactile_data_level` 有三种语义：

| 等级 | 内容 | 来源/用途 |
| --- | --- | --- |
| `NONE` | 没有新鲜触觉数据 | 未连接、超时或尚未收齐 |
| `SUMMARY` | 每个模块的三轴摘要和模块有效位图 | 轻量实时显示和快速判断 |
| `FULL` | 逐触元阵列，带完整批次 CRC/sequence | 阵列显示、触点定位和全量 CSV |

触觉窗口中的三轴合力属于摘要信息，不能当作逐 taxel 分布。要恢复具体触点，
必须得到 `FULL` 数据并保持 sequence、summary sequence 和 CRC 一致。

## 7. 逐 taxel CSV

启用 Save Data 的触觉全量选项后，`05_触觉全量.csv` 每行包含：

```text
sample_index, host_time, p4_time_ms,
finger_index, finger_name, sensor_index, row, col,
fx, fy, fz, force_mag
```

恢复方法：

1. 按 `finger_index` 分组；
2. 再按 `sensor_index` 分组；
3. 用 `row/col` 放回二维阵列；
4. `fx/fy/fz` 是三个轴的原始/处理后值，`force_mag` 是当前记录器计算的合力幅值；
5. 以 `p4_time_ms` 和 sequence/记录时间区分不同采样批次；
6. 缺失模块或缺失批次不要用上一帧伪造“在线”。

当前数据记录实现位于 `desktop/ui/ui_app.py` 的 `_write_tactile_full_rows()`，
字段契约位于 `desktop/core/data_recording/topic_schema.py`。

## 8. 通信排查最小路径

```text
S3 SPI 原始读数
  → S3 CRC/错误诊断
  → S3 CAN 帧与批次重组
  → P4 传感器状态/sequence/CRC
  → desktop packet router/state reducer
  → HandModel tactile_data_level
  → UI/CSV
```

任何一层失败都可能表现为“触觉窗口无数据”。先区分是没有 SPI 成功、没有
CAN 完整批次、上位机未连接正确 S3 端口，还是只有 FULL 大包超时。
