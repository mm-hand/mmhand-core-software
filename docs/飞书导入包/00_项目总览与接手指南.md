# MMHand 项目总览与接手指南

最后核对：2026-09-10

## 1. 项目目标

MMHand 是一套 21 关节、27 路舵机的腱绳驱动灵巧手系统：

- 上位机负责 GUI、命令输入、标定文件、恢复编排、ROS2/Replay 和数据记录；
- P4 负责实时状态机、舵机控制、自动标定、Rope Init、故障保护和四路舵机 UART；
- S3 负责 21 路磁编码器、触觉 SPI 采集以及向 P4 的 CAN 上报；
- 机械、舵机、磁编、触觉和绳路属于实物交付内容，源码不能代替现场确认。

## 2. 总体数据流

```text
Wuji/ROS2/GUI/Replay
        │ 21 路关节目标
        ▼
desktop HandBackend → HandController → P4 HostComm
                                      │
                 ┌────────────────────┼───────────────────┐
                 ▼                    ▼                   ▼
          SystemStateTask      MotionControlTask      AutoCalibrationTask
                 │                    │                   │
                 └──────────── Actuator/Safety ───────────┘
                                      │
                         四路 1 Mbit/s 舵机 UART
                                      ▼
                                  27 路舵机

21 路磁编 + 触觉 → S3 → 1 Mbit/s CAN → P4 → HostComm → HandModel → UI/CSV
```

P4 主串口打开只代表串口句柄成功，不能单独证明状态同步、舵机路由、磁编、
多圈恢复或 `READY` 已完成。S3 触觉串口是独立链路，P4 连接正常不等于触觉
连接正常。

## 3. 核心概念

| 概念 | 含义 |
| --- | --- |
| J00-J20 | 软件关节编号，角度和磁编按此编号组织 |
| M00-M26 | 软件电机通道编号，当前硬件 servo ID 通常相同，但 BUS 由启动扫描发现 |
| raw | 单圈或舵机协议原始位置数据 |
| logical ABS | P4 当前会话中的多圈绝对位置，控制和恢复使用它 |
| LUT | 标定得到的关节角到舵机 ABS/腱绳坐标映射 |
| active scope | 本次控制或标定实际允许使用的关节/电机掩码 |
| owner | 当前允许发布舵机目标的业务所有者，如 Control、Calibration、Rope Init |
| Turn Unknown | P4 尚未确认某路舵机多圈坐标，普通控制必须阻止 |
| READY | 反馈、标定、路由、多圈和安全门禁满足后的可控状态 |

## 4. 接手第一天的顺序

1. 保存 `git status --short`、`git rev-parse HEAD`、当前分支和实际构建日志。
2. 记录 P4/S3 型号、FQBN、串口、舵机 ID、实物 BUS、手型、左右手和设备序列号。
3. 阅读 `01`，使用上位机完成一次“连接但不运动”的状态检查。
4. 阅读 `02`，能从 `SystemAssembly.cpp` 追到 HostComm、SystemState、MotionControl 和 ServoBus。
5. 阅读 `03`，理解 Manual、Auto/LUT、Rope Init 和多圈 JSON 的先后关系。
6. 阅读 `04`，确认 P4 舵机 UART、S3 两条 SPI 和 CAN 接线。
7. 按 `05` 的顺序完成单关节、双腱、恢复、触觉和记录验证。
8. 将未验证事项填入交接表，不把“源码看起来合理”写成“实机已通过”。

## 5. 关键安全原则

- 先确认舵机在线、路由唯一、反馈新鲜，再扩大 active scope。
- `ENABLE` 是取得控制权的动作，不应被理解为“发送一个默认位置”。
- `E-STOP` 是锁存式安全停止；原因排除后需要 `RESET/Clear Fault`，再重新 `ENABLE`。
- `Pause` 保留目标缓存，`Resume/ENABLE` 是否允许恢复还要检查模式和设备身份。
- 标定动作、Rope Init、直控和负反馈不能同时争抢舵机目标所有权。
- 设备身份、URDF 映射、Manual CRC 和标定 JSON 必须一致。
