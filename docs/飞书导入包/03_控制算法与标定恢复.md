# 控制算法与标定恢复

最后核对：2026-09-10

## 1. 坐标和数据

- `q_ref`：上位机/P4 当前周期的目标关节角，单位 degree。
- `q_fb`：S3 磁编映射后的实际关节角，单位 degree。
- `A_i`：第 `i` 台舵机当前可信 logical ABS，单位 counts。
- `L_i(q)`：标定 LUT 在角度 `q` 对应的 logical ABS/腱绳坐标。
- `s_i`：LUT 局部或内部点拟合斜率，单位 counts/degree。
- `sign_i`：raw ABS 与腱绳收紧方向之间的符号转换。

当前标定数据结构是每个关节一份 `JointCalibrationResult`。单腱只使用 LUT
第 0 路；双腱使用两路并且 LUT 行必须和 `Mxx` 通道严格匹配。

## 2. 单电机关节当前公式

基础误差：

```text
e = q_ref - q_fb
```

控制器调用 `ControlSolver::compute()`，对 21 个关节分别运行独立 PID：

```text
u_pid_tendon = A_tendon + PID(e, dt)
u_pid_raw    = sign * u_pid_tendon
```

这里的 `A_tendon` 是把当前舵机 ABS 转到腱绳坐标后的值，`dt` 使用实际控制
周期，异常时才回退 10 ms。PID 基础参数在 `ControlConfig.h`，当前单腱默认
`Kp=5.7, Ki=0, Kd=0`；有效 LUT 下还会按误差大小和 LUT 斜率调度 Kp：

- `|e| <= 0.8°`：使用 `Kp=20`，保证接近目标仍有推进力；
- `2.5°` 到 `3.0°`：在局部斜率增益和平均斜率增益之间平滑过渡；
- 大误差：使用 LUT 全跨度平均斜率乘 `0.41`；
- 局部段：紧绳侧使用局部斜率乘 `0.9`，松绳侧按大误差增益处理。

最终还会进行：

1. 单腱 LUT 与当前电机通道匹配检查；
2. 松端 `500 counts`、紧端 `1000 counts` 的 LUT 运行裕量；
3. 当前会话 logical 行程钳位；
4. 反馈无效、离线、过载和碰撞 HOLD 处理。

速度前馈代码仍保留，但当前 `kSingleTendonVelocityFeedforwardEnabled=false`，
因此当前默认控制不增加该项。单腱换向连续补绳当前启用：目标反向累计达到
`1°` 后从 `60 counts` 起按实际 `dt` 连续增加，最大 `140 counts`，磁编沿新方向
实际推进 `0.25°` 后退出。

## 3. 双腱关节当前公式

双腱不是把一个结果复制给两台电机，而是分别使用 `L_1`、`L_2`。

当 LUT 至少有 4 个样本时，代码去掉首尾样本，对内部等角度点做最小二乘斜率：

```text
s_i = Σ[j=1..N-2] (q_j - q_mid) * L_i(q_j)
      / Σ[j=1..N-2] (q_j - q_mid)^2
```

若内部斜率有效，当前 PID 模型为：

```text
r_i = s_i * q_ref
f_i = s_i * q_fb
e_i = r_i - f_i

c_i = Kp_i * e_i
    + Ki_i * Σ(e_i * dt)
    + Kd_i * LPF((v_ref_i - v_fb_i))

raw_cmd_i = A_i + round(c_i)
```

若斜率不可用，则 `r_i/f_i` 回退为各自 LUT 插值值。当前双腱参数为
`Kp=0.80, Ki=0, Kd=0`，积分上限为 0；D 项上限为 100 counts。之后每台电机
独立经过自己的 LUT 范围、松/紧端裕量和会话行程边界。

双腱还保留一个小幅“配对恢复”项：它从实际反馈与模型的偏差中去掉沿关节
运动方向的分量，只对剩余相对偏差做限速恢复。当前配置为 gain `0.05`、死区
`10 counts`、每周期最多 `3 counts`，它不是张力传感器，也不能证明张力恒定。

## 4. 标定流程

```text
Device Check 写 Manual
  → P4 RAM + 桌面 JSON 读回核验
  → Auto Calibration
  → JointCalibrationResult 发布
  → 桌面按 Jxx 增量合并保存
  → 标定完成后自动 Rope Init
  → READY
```

Manual 端点是 21 路磁编的机械参考；Auto 结果包含角度范围、ABS 端点、
LUT、映射版本、URDF CRC 和 Manual 条目 CRC。双腱 LUT 两行的 `Mxx` 顺序
必须与 `HardwareMap.cpp` 的执行器顺序一致，不能只看关节编号。

## 5. 掉电、重启和重烧录

- P4 RAM 中的 Manual、Auto/LUT 和运行状态会丢失；桌面 JSON 是跨重启恢复源。
- P4 启动先将已知电机标为 `Turn Unknown`，等待上位机使用匹配的多圈 runtime
  锚点恢复 logical ABS；这不等于每次上电都执行 `RESET ZERO`。
- 普通 P4 重启恢复的是原来的 logical ABS 会话，不应重定义硬件零点。
- `RESET ZERO` 属于维护/标定动作，会改变硬件圈数基准；执行后必须失效相关
  多圈锚点和相关 Auto/LUT，除非已产生新的有效标定结果。
- 设备身份变化、产品指纹变化、URDF mapping CRC 不一致或锚点无效时，控制应
  保持阻止，不能用 raw 单圈值猜测多圈。
