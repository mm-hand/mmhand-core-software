# 上位机架构与使用流程

最后核对：2026-09-10

## 1. 正式启动入口

统一入口是 `desktop/__main__.py`，实际参数分发在 `desktop/app/entry.py`。

```powershell
# GUI，默认装配 ROS2 输入桥
python -m desktop ui --mode monitor

# 指定 P4 主串口
python -m desktop ui --mode monitor --port COMx

# 同时指定独立的 S3 触觉串口
python -m desktop ui --mode monitor --port COMx --tactile-port COMy

# 命令行兼容入口
python -m desktop cli --port COMx
```

没有 ROS2 环境时显式使用 `--no-ros2`。ROS2 桥启动成功不代表获得 P4 输出授权；
用户仍需在 GUI 点击 `ROS2 INPUT`，或在 CLI 使用对应授权操作。

Windows 图标启动使用仓库根目录的 `start_mmhand.cmd`。它优先使用
`MMHAND_PYTHON`，其次尝试项目 `.venv`、当前虚拟环境、`py -3` 和 `python`。
快捷方式可由 `tools/create_desktop_shortcut.ps1` 生成。交付前应把快捷方式绑定
到实际存在的 Python，不要把另一台电脑的绝对路径带过来。

## 2. 分层和调用边界

```text
ui / ROS2 / Replay
        ▼
HandBackend（公共门面）
        ▼
HandController（命令事务、状态、恢复）
        ▼
communication（传输、解帧、路由、归并、ACK）
        ▼
P4 串口协议
```

| 层 | 当前职责 | 禁止事项 |
| --- | --- | --- |
| `desktop/app` | 参数解析、Qt/CLI/ROS2 生命周期 | 不实现协议和安全判断 |
| `desktop/ui` | 控件、显示、用户操作意图 | 不直接访问串口或复制协议 |
| `desktop/core/hand_backend.py` | UI、CLI、ROS2、Replay 共用门面 | 不让页面绕过门面改设备 |
| `desktop/core/core_logic.py` | 连接、命令、ACK、标定加载、多圈恢复 | 不依赖 Qt、ROS2 页面 |
| `desktop/core/communication` | 原始串口、解帧、状态归并、事件保序 | transport 不解释业务 |
| `desktop/core/data_recording` | Topic/事件转 CSV | 记录不能改变控制状态 |
| `desktop/visualize` | 离线 Plotly 和数据分析 | 先确认 CSV schema 和时间轴 |

典型状态路径：

```text
SerialTransport → FrameDecoder → P4PacketRouter → StateReducer
→ HandModel → HandController/HandBackend → UI 和 Recorder
```

连续状态可以采用 latest-value；ACK、安全事件和操作事件必须独立保序，不能
为了简化而并入会丢旧事件的状态邮箱。

## 3. 推荐操作顺序

### 3.1 日常启动

1. 给 P4、S3、舵机和机械手供电，确认机械空间安全。
2. 启动 GUI，选择 P4 主串口；不要把 S3 串口当 P4 主串口。
3. 等待状态同步、路由扫描和多圈恢复，不要看到“串口打开”就立即控制。
4. 检查舵机在线、磁编在线、`Turn Unknown`、标定状态和 `Status Age`。
5. 选择尽可能小的 `Control Set`，进入 `Joint Channels` 或 `Motor Channels`。
6. 点击 `ENABLE`，等待状态进入可控状态；随后再移动滑条或发送目标。
7. 遥操时确认 ROS2 输入已授权；Replay 时确认轨迹、作用域和模型契约。

### 3.2 首次标定

1. 在 `Device Check` 采集 Manual Min/Max，确认 raw 方向和跨度。
2. 点击 `Write Modified`，等待 ACK、读回、CRC 和 JSON 保存成功。
3. 选择需要标定的关节，确认舵机、磁编、路由和机械空间均正常。
4. 点击 `Calibrate`，标定期间不要切换模式或发送普通目标。
5. 标定成功后当前固件路径会自动进入 Rope Init 收尾流程。
6. 只有看到 `Calibration: Success`、`Multi-turn: Known` 和 `System: Ready` 后才开始控制。

### 3.3 使用已有标定文件

1. 设备必须属于同一产品指纹和同一机械映射。
2. 在停止状态使用 `Load Calibration...`。
3. 上位机会先恢复 P4 RAM 中的 Manual，再加载 Auto/LUT/ABS Limit。
4. 等待多圈恢复结果和 READY 条件收敛，失败时按具体 Mxx/Jxx 处理。
5. 不要用一只手或另一套舵机的 JSON 覆盖当前设备。

## 4. 主要按钮和状态

| 控件 | 当前作用 |
| --- | --- |
| `ENABLE` | 按当前模式和 active scope 取得控制权；正常情况下应保持可信当前位置 |
| `E-STOP` | 锁存式停止，取消测试/Replay/ROS2 输出；排除原因后需清故障 |
| `Pause` | 暂停输出并保留目标缓存；恢复仍受模式、scope 和状态门禁约束 |
| `ROS2 INPUT` | 只授权外部 ROS2 目标，不代替普通控制器启动 |
| `Calibrate` | 对当前选择的关节执行自动标定，成功后进入 Rope Init |
| `Clear Fault` | 发送 reset 并清理控制状态，之后必须再次 ENABLE |
| `Release Rope` | Device Check 维护动作；会清理相关坐标/标定并释放绳路，必须确认机械安全 |
| `Write Modified` | 写入 Manual 修改项并读回核验 |
| `Clear Manual` | 清除 Manual 参考，相关标定和负反馈会失效 |

状态条重点看：`System`、`Calibration`、`Overload`、`Collision`、`Multi-turn`、
`Status Age`。`overload` 要显示全名和具体 Mxx；多故障使用 Details 查看完整
Jxx/Mxx、规则 ID、原因和建议，不只看一个摘要标签。

## 5. 触觉和数据记录入口

触觉窗口使用独立的 S3 串口，可显示触觉摘要、模块在线状态、三轴合力和在有
全量帧时的 taxel 阵列。`Save Data` 默认保存基础总表；需要逐 taxel 数据时，
在记录选项中启用“触觉全量”，生成 `05_触觉全量.csv`。
