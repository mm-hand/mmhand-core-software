# P4 固件架构与状态机

最后核对：2026-09-10

## 1. 入口和任务

正式入口：`ESP32-P4/ServoBoardMain/ServoBoardMain.ino`。
共享运行数据由 `src/app/SystemAssembly.cpp` 创建并装配任务。

| 任务 | 当前职责 | 优先级 | 周期/说明 |
| --- | --- | ---: | --- |
| `HostCommTask` | 上位机帧接收、解析、ACK 和状态上报 | 2 | 5 ms 兜底，RX 可提前唤醒 |
| `SystemStateTask` | 顶层状态、owner、START/STOP/RESET、Rope Init | 5 | 安全状态机最高业务优先级 |
| `S3CanRxTask` | 接收并重组 S3 磁编/触觉 CAN 批次 | 3 | 持续接收和完整性检查 |
| `MotionControlTask` | 10 ms 角度闭环和舵机目标构建 | 4 | 100 Hz 控制周期 |
| `ServoBusTask` | 四路 UART 舵机扫描、反馈、目标发送和恢复 | 3 | 10 ms 服务周期 |
| `AutoCalibrationTask` | 自动标定状态机和标定结果发布 | 2 | 由 SystemState 控制所有权 |
| `RuntimeMonitorTask` | 任务运行时间和资源指标 | 1 | 按需上报 |

准确配置以 `src/config/TaskConfig.h` 和 `SystemAssembly.cpp` 为准。不要只改
注释或脚本中的任务优先级。

## 2. 目录边界

| 目录 | 作用 |
| --- | --- |
| `src/app` | Arduino 入口、共享对象和任务装配 |
| `src/config` | 板级引脚、周期、算法、标定和安全参数 |
| `src/data` | 跨任务纯数据结构和枚举 |
| `src/hal` | UART、TWAI/CAN、飞特舵机等硬件封装 |
| `src/modules/actuator` | 舵机命令 gateway、目标批次和 owner 相关结构 |
| `src/modules/calibration` | 标定数学、LUT、Manual/Auto 运行数据 |
| `src/runtime` | 共享运行上下文和服务适配器 |
| `src/safety` | 纯安全策略、规则目录和事件证据 |
| `src/tasks` | 各 FreeRTOS 任务和周期服务 |
| `src/generated` | 由 schema/def 生成的协议和安全目录，不手改 |

## 3. 状态主线

```text
上电/连接
  → UNCONTROLLABLE 或 IDLE
  → 路由、反馈、Manual/Auto、multi-turn 检查
  → READY
  → RUN_FEEDBACK 或 RUN_DIRECT

标定：CALIBRATION_RUNNING → 标定结果发布 → ROPE_INIT_RUNNING → READY
暂停：RUN_* → PAUSED → 由合法恢复流程回到可控状态
异常：任意运动状态 → HOLD/UNCONTROLLABLE/E-STOP/FAULT
```

状态名称和转换以 `src/data/SystemTypes.h`、
`src/tasks/system_state/SystemEventDispatcher.cpp`、
`src/tasks/system_state/SystemStateCoordinator.cpp` 为准。

## 4. 命令执行链

```text
HostCommTask
  → HostCommandDispatcher/Router
  → SystemEventDispatcher
  → owner 与 active scope
  → MotionControlTask 或 AutoCalibration/RopeInit
  → ActuatorCommandGateway
  → ActuatorSafetyPolicy
  → ServoBusTask
  → FeetechServoDriver
```

关键约束：

- parser 只负责识别帧，不直接写舵机；
- 命令要通过状态准入、owner、路由、反馈新鲜度、范围和租约检查；
- `ServoBusTask` 是舵机反馈和目标发送的硬件边界；
- 一台舵机离线时应隔离对应通道，不能让底层 UART 无限重启拖死其他 BUS；
- 一个批次构建失败时不能发布已经追加的部分命令；
- 上位机心跳租约超时由 P4 执行预定的保持/停止策略。

## 5. READY 需要什么

READY 不是单个按钮的结果，至少要检查：

- 当前系统没有阻断性 fault 或 E-STOP；
- active scope 内舵机在线且每台有唯一可控 BUS 路由；
- 对负反馈而言，S3/CAN/磁编反馈有效且新鲜；
- Manual/Auto/LUT/ABS Limit 与当前模型、产品指纹和映射契约一致；
- active 电机的 logical ABS 多圈坐标已知；
- Rope Init 事务没有运行、失败或被取消；
- 当前 owner 与控制模式一致。

## 6. 代码阅读入口

1. `SystemAssembly.cpp`：看对象和任务如何创建。
2. `SystemRuntimeContext.h`：看跨任务共享数据和所有权。
3. `SystemEventDispatcher.cpp`：看 START、RESET、标定、Rope Init 分发。
4. `SystemStateCoordinator.cpp`：看周期推进。
5. `DirectCommandCoordinator.cpp`：看直控目标接管和代次。
6. `MotionControlService.cpp`：看每 10 ms 控制编排。
7. `ServoBusService.cpp`、`ServoFeedbackPublisher.cpp`：看反馈、路由和多圈恢复。
8. `SafetyRuleCatalog.def`、各 `*SafetyPolicy.cpp`：看拒绝和故障语义。
