  • 通用 0x1A APPLIED 表示执行层完成本批同步写调用，未证明逐台接收或机械到位；反馈继续验证运动。

  • 协议支持执行层给出的部分 applied/rejected 位图，整体 REJECTED；上位机不推进校准。当前 SDK 调用不能检测所有物理丢帧。

取消、故障及重试

  • PAUSE 在校准和 Rope Init 期间被拒绝。
  • STOP 校准搜索 → UNCONTROLLABLE，校准 status=IDLE；校准收尾被 STOP 中断 → WARN。
  • 校准搜索算法失败或阻断故障 → UNCONTROLLABLE、FAILED；校准收尾 Rope Init 阻断故障 → UNCONTROLLABLE、WARN。
  • 失联 Hold 确认后取消；搜索 FAILED / CONTROL_LOST，收尾 WARN。

新 CALIBRATE 入口会清 calibration_fault_latched；代码没有把“校准失败后先 RESET”设为独立硬门禁。其他锁存故障仍可能在进入后由监督阻断。

可信何时失效，以及哪些数据不能替代它

P4 上电把全部有效电机标为 unknown。连续同步读失败 3 次、在线反馈年龄 ≥80 ms（维护宽限/未轮询通道除外），或 UART restartTransport，会触发驱动会话失效：冻结原可信锚点，清 online、initialized、reliable、configured、logicalOffset 与 turnCount。重新 online 不会直接恢复旧圈数；反馈发布随后把无路由或已离线失效电机置 unknown。

驱动 reliable 与共享 unknown 的更新并非原子同步：服务在成功路径清 unknown；反馈发布也会在电机 online 且驱动 reliable 时自动清 unknown，无驱动或已离线失效时置 unknown。这一同步不会凭空建立驱动的可信基准。

硬件圈数越界设置独立 overflow，关力矩并 STOP，不直接撤销 reliable 或置 unknown。Reset Zero 的 RESET 已响应后若配置/新反馈失败，驱动基准也可能已被撤销，不能把失败视为完全未改变状态。

Manual、Auto/LUT、工作限位、舵机 raw、logical ABS 与可信位是不同数据。校准的 readLatestMotorServoAbs() 只检查通道、队列与 online，不检查 unknown 或帧年龄。发布快照 timestamp 会更新，但数值可能来自缓存（例如前两次读失败仍在线）；不能把“读到数值”或“新快照”当成每台电机都新测量、已可信。

公共判断 D 的实际顺序

  1. 急停锁存，或 controllableEntryReady() 不通过 → UNCONTROLLABLE。
  2. 底层可控且完整反馈门禁满足 → READY。
  3. 底层可控、反馈未 READY 且 recoverableBelowMask 非 0 → RECOVERY_REQUIRED。
  4. 其余底层可控情况 → IDLE。

READY 的完整门禁包含 Manual、requiresCan、Auto/映射版本与 URDF/Manual CRC、多圈/overflow、ABS 工作限位、CAN/磁编/映射快照的新鲜与有效、无系统故障和工作空间下边界迟滞。进入需连续 3 个新样本 outsideCounts ≥−24；退出需连续 3 个新样本 <−48。超上边界不会直接撤 READY。本函数没有显式检查 LUT valid/count。
